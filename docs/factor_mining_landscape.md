## 0. 先统一几个概念

### 0.1 因子到底在解决什么问题

一个因子就是一个**截面打分函数**：

```text
f : 截至 t 日收盘前可得的全部信息  →  R^N      （N = 当天可交易的股票数）
```

评价标准不是「预测得准不准」，而是「**排序对不对**」：
今天打分高的一组股票，未来 h 天的收益是否系统性地高于打分低的一组。

换成 ML 的话说，因子挖掘是这样一个问题：

| ML 视角 | 因子业务里的对应物 |
| --- | --- |
| 任务 | **每天一个 query、N 个 item 的 learning-to-rank** |
| 指标 | 每天算一次 Spearman 相关（RankIC），再看它在时间上的均值和稳定性（ICIR） |
| 信噪比 | 极低。日度 RankIC 能稳定做到 0.03–0.05 就算好因子，也就是说 R² 大约是 0.1% 的量级 |
| 分布 | 强非平稳：市场状态会切换，因子会衰减，而且被发现的因子会被交易掉（拥挤） |
| 样本 | 表面上是 N×T 行，但同一天的样本高度相关，**有效样本量接近 T（交易日数）而不是 N×T** |

最后一条是 ML 背景的人最容易低估的：十年日频数据，真正独立的样本大约只有两千多个「天」。

### 0.2 Alpha101 是什么，能当什么用

Alpha101 出自 Kakushadze (2015) 的 *101 Formulaic Alphas*，是 WorldQuant 公开的 101 个实盘公式因子。
它的特点：

- 只用日频量价数据：`open`、`high`、`low`、`close`、`volume`、`vwap`、`returns`、`cap`，外加行业分类。
- 由一套固定算子拼成：`rank`、`delay`、`delta`、`correlation`、`covariance`、`ts_rank`、`ts_min/max`、`ts_argmax/argmin`、`decay_linear`、`scale`、`signedpower`、`indneutralize`、`sum`、`stddev`、`product`。
- 论文给出的平均持有期约 0.6–6.4 天，两两平均相关性约 15.9%。说明这是一组**短周期、彼此相关性不高的量价信号**。

以它为起点，Alpha101 可以扮演三种角色，后面每一章都会用到其中一种或几种：

| 角色 | 含义 | 用到这个角色的方法 |
| --- | --- | --- |
| **① 特征** | 101 个因子值直接作为模型输入 | ML 合成、深度学习（作为附加输入） |
| **② 语法** | 它的字段和算子构成一门领域专用语言（DSL），新因子用同一套语法表达 | 模板枚举、遗传规划、强化学习、LLM 智能体 |
| **③ 基准** | 新因子必须**相对 Alpha101 有增量**，否则只是换了个写法 | 所有方法 |

角色 ③ 最容易被忽视，却是最重要的。挖出一个 IC 很高、但和 Alpha#12 相关性 0.9 的因子，等于什么都没挖到。

### 0.3 所有方法共用的验证漏斗

不管候选因子是怎么生成的，最后都要过同一个漏斗。**方法之间的差别只在漏斗入口（怎么生成候选）**：

```text
生成候选 ─► 单因子测试 ─► 增量 / 正交检验 ─► 稳健性检验 ─► 可交易性检验 ─► 入库 + 衰减监控
          RankIC/ICIR/  对 Alpha101 与风格   分池、分年、     换手、成本、
          分组/多空      因子回归后看残差 IC   参数扰动         涨跌停、容量
```

单因子测试的口径见[因子挖掘专题 §4](factor_mining_topic.md)；增量检验和多重检验见本文 §11。

## 1. 人工研究驱动：假设 → 公式 → 验证

**依赖基础因子库：强依赖。** 这是业内实盘因子最主要的来源，其他所有方法都是在提高它的效率。

### 1.1 思路

研究员从一个**可解释的市场机制**出发，比如「过度反应之后会反转」「知情交易者会在成交量里留下痕迹」「分析师上调评级有滞后效应」，
把它写成公式，再用数据验证。
好的人工因子，通常都能回答一句：「这笔钱是谁亏给你的，为什么他会持续亏？」

### 1.2 第一步：把 Alpha101 拆成「语义单元」

Alpha101 的公式看起来是乱码，但拆开后，大部分只由少数几种语义单元组成：

| 语义单元 | 典型写法 | 市场含义 | 例子 |
| --- | --- | --- | --- |
| 短期反转 | `-delta(close, d)`、`-ts_rank(returns, d)` | 短期过度反应，随后修正 | Alpha#9、#10 的主体 |
| 量价相关 / 背离 | `-correlation(rank(open), rank(volume), d)` | 放量上涨和缩量上涨含义不同 | Alpha#6、#13、#15 |
| 成交量冲击 | `volume / adv20`、`delta(volume)` | 异常成交往往伴随信息事件 | Alpha#12、#25 |
| 日内结构 | `(close - open) / (high - low)`、`vwap - close` | 日内的买卖力量对比 | Alpha#33、#41、#101 |
| 波动 / 尾部 | `stddev(returns, d)`、`ts_argmax(...)` | 风险偏好与彩票效应 | Alpha#1、#18 |

先把 101 个公式按语义单元归类，你就得到了一张「主题地图」。
后续的所有改造，都是在这张地图上**沿着某个维度做可解释的变化**。

### 1.3 第二步：因子工厂——系统化地做变体

对每个语义单元，可以沿以下几个维度扩展：

| 维度 | 做法 | 为什么可能有效 |
| --- | --- | --- |
| 窗口 | d ∈ {3, 5, 10, 20, 60} | 同一机制在不同时间尺度上强弱不同 |
| 字段替换 | `volume` → `amount` / 换手率 / 自由流通换手率；`close` → `vwap` | A 股里换手率通常比绝对成交量更可比 |
| 截面处理 | `rank` / `zscore` / 行业中性化 / 市值中性化 | 去掉行业和规模的暴露，留下纯 alpha |
| 相对化 | 行业内相对（`IndRel_`）、相对自身历史的 z-score（`5YRel_`） | 这正是标普把几十个基础指标扩成 429 个因子的办法 |
| 条件化 | 只在高换手、低波动、大盘股、有新闻日等子集上计算，或者分段取值 | 很多效应只在特定状态下成立 |
| 平滑 | `decay_linear`、EMA、N 日均值 | 降低换手，用一点点 IC 换大量交易成本 |
| 迁移 | 把日频公式放到周频或分钟级数据上 | 同一机制在不同频率上也许同样成立 |

```python
# 因子工厂的最小骨架：语义单元 × 变体维度 → 候选因子
SEMANTIC_UNITS = {
    "pv_corr": lambda p, v, d: -ts_corr(rank(p), rank(v), d),
    "reversal": lambda p, v, d: -ts_delta(p, d),
}
FIELDS_P = ["close", "vwap", "open"]
FIELDS_V = ["volume", "amount", "turnover"]
WINDOWS = [5, 10, 20]
POSTPROC = [identity, ind_neutralize, lambda x: decay_linear(x, 5)]

candidates = [
    (name, fp, fv, d, pp)
    for name in SEMANTIC_UNITS for fp in FIELDS_P for fv in FIELDS_V
    for d in WINDOWS for pp in POSTPROC
]   # 2 × 3 × 3 × 3 × 3 = 162 个候选，每一个都要记账（见 §11 多重检验）
```

### 1.4 第三步：条件化和交互——人工因子的真正增量

单纯换窗口、换字段挖出来的因子，和原因子相关性往往很高，增量有限。
真正有增量的人工因子，大多来自**条件化**：

- **信息驱动 vs 非信息驱动的价格变动**：有公告、新闻的当天，价格变动更可能是信息反映，不会反转；没有信息的放量变动更可能是噪声交易，会反转。于是可以用「无公告日的反转因子」替代普通反转因子。
- **分域**：同一个量价因子，在小盘股里往往是反转，在大盘股里可能变成动量。按市值或流动性分域分别定义方向。
- **状态依赖**：市场整体波动高的时期，反转效应通常更强。可以用市场状态给因子加权。

这些交互往往也能从 §5 的 ML 模型里「读出来」（SHAP 交互值），再回到这里写成显式公式。**人工和 ML 是一个闭环**，不是互相替代。

### 1.5 优缺点

- 优点：可解释，衰减慢，出问题时知道原因，也方便向投委会或客户解释。
- 缺点：慢，依赖研究员的经验；变体做多了，一样有多重检验问题。

## 2. 模板化枚举：结构化的暴力搜索

**依赖基础因子库：依赖 Alpha101 的语法（角色 ②）。** 这是 WorldQuant 自己的 BRAIN 平台和很多卖方金工的主力做法，比遗传规划更「笨」，但更可控。

### 2.1 思路

与其让算法随机进化，不如**先定下公式骨架（模板），再系统地填槽位**：

```text
模板：  op_outer( op_inner( FIELD_A, d1 ), d2 )  ×  op_post
槽位：  op_outer ∈ {ts_rank, ts_zscore, decay_linear, delta}
        op_inner ∈ {ts_corr(·, FIELD_B), ts_std, ts_mean, delta}
        FIELD_A, FIELD_B ∈ 字段表
        d1, d2 ∈ {5, 10, 20, 60}
        op_post ∈ {rank, ind_neutralize, identity}
```

### 2.2 从 Alpha101 里反向抽取模板

Alpha101 本身就是最好的模板来源。做法是把 101 个公式解析成抽象语法树（AST），然后**把具体的字段和常数替换成槽位**：

```text
Alpha#6:   -1 * correlation(open, volume, 10)
抽象后：   -1 * correlation(<PRICE_FIELD>, <VOLUME_FIELD>, <WINDOW>)

Alpha#12:  sign(delta(volume, 1)) * (-1 * delta(close, 1))
抽象后：   sign(delta(<VOLUME_FIELD>, <W1>)) * (-1 * delta(<PRICE_FIELD>, <W2>))
```

101 个公式去重后，通常能得到几十个结构不同的模板。每个模板再用新的字段表（换手率、资金流、北向持股……）和窗口表来填，
就能得到成千上万个「在结构上被验证过」的候选。

### 2.3 让枚举可行的工程手段

搜索空间是组合爆炸的，靠以下手段压缩：

1. **类型系统**：给字段标上量纲（价格、成交量、比率、无量纲排名），禁止无意义的组合，比如 `价格 + 成交量`。窗口参数只能是整数常数。
2. **等价变换去重**：`rank(rank(x)) = rank(x)`，`ts_rank(rank(x), d) ≈ ts_rank(x, d)`，`-(-x) = x`。先做规范化再算。
3. **公共子表达式缓存**：`ts_corr(rank(vwap), rank(volume), 10)` 这种中间结果被大量模板共用，算一次缓存起来。
4. **分层筛选**：先在一小段时间、一个股票池上粗筛，淘汰掉 90%，再对剩下的做全样本精测。

### 2.4 WorldQuant 的筛选口径（参考）

BRAIN 平台公开文档里用的综合评分是：

```text
Fitness = Sharpe × sqrt( |Returns| / max(Turnover, 0.125) )
```

它同时奖励高夏普、高收益、低换手。另外还要求新因子和自己已提交的因子的**相关性低于阈值（常见的是 0.7）**才算有效提交，
这就是角色 ③ 的工程化落地。

### 2.5 和遗传规划的区别

| 维度 | 模板枚举 | 遗传规划 |
| --- | --- | --- |
| 搜索方式 | 系统地、确定性地遍历 | 随机进化，有选择压力 |
| 公式结构 | 被模板限定，可解释性好 | 结构自由，容易长出怪公式 |
| 可控性 | 高：知道搜了什么、没搜什么 | 低：每次跑的结果不同 |
| 发现新结构的能力 | 弱：跳不出模板 | 强 |

实务上常见的组合是：**先用模板枚举把「已知结构 × 新字段」吃干净，再用遗传规划去找新结构。**

## 3. 遗传规划 / 符号回归

**依赖基础因子库：依赖语法（②），也可以把 Alpha101 的因子值直接当叶子（①）。**
平台实现的细节见[因子挖掘专题 §3](factor_mining_topic.md)，这里只讲更深入的设计选择。

### 3.1 表示方式：Alpha101 的两种用法

| 用法 | 叶子 | 函数集 | 评价 |
| --- | --- | --- | --- |
| **A. 从原始数据开始**（推荐） | `open, high, low, close, vwap, volume, returns, amount, turnover` + 随机常数 | Alpha101 的全部算子 | 和 Alpha101「同源」：Alpha101 看起来就是这种方法的产物，你在挖第 102、103… 个 |
| **B. 在 Alpha101 之上组合** | 101 个 alpha 的因子值 | 截面和二元算子为主，少量时序算子 | 平台（用标普因子当叶子）就是这种。容易产生和原因子高度相关的冗余公式 |

另外可以用 Alpha101 做**种群初始化**：初代种群里直接放入 Alpha101 原公式及其子树，
进化从「已经被验证过的好结构」附近开始，比从随机公式开始收敛快得多。

**强类型 GP** 很重要：窗口参数只能是整数常数，时序算子的第一个参数必须是序列。gplearn 默认不支持，需要自己实现，或者用 DEAP 的 `PrimitiveSetTyped`。
不做类型约束的话，大量个体会是非法或无意义的公式，白白浪费算力。

### 3.2 适应度设计：比「IC 最大」更重要的事

只用训练段的 RankIC 均值当适应度，一定会收敛到过拟合和冗余。业内常见的改进有：

**① 稳定性而不是均值**：用 ICIR 或 IC 的 t 值，而不是 IC 均值。

**② 多目标**：用 NSGA-II 之类的方法同时优化「IC、复杂度、和已有库的最大相关性」三个目标，最后取帕累托前沿，而不是加权成一个数。

**③ 增量适应度（最关键）**：让进化直接优化「对 Alpha101 的增量」。有两种做法：

```text
做法 1（残差目标）：
    每天把未来收益对 Alpha101 的 101 个因子（加行业、市值）做截面回归，取残差 ε_t
    适应度 = RankIC(候选因子, ε_t)
    → 候选因子只有解释了 Alpha101 解释不了的部分，才会拿高分

做法 2（相关性惩罚）：
    适应度 = ICIR(候选) − λ · max_k |corr(候选, alpha_k)|
```

**④ 多轮挖掘**：每轮结束后，把入选的新因子加进「已有库」，重新计算残差目标，再跑下一轮。
这样每一轮都被迫去找新东西，而不是反复挖到同一个信号的变体。

### 3.3 防过拟合

除了平台已经在做的样本内 / 样本外切分和长度惩罚，还可以加上：

- **多股票池一致性**：适应度取候选在 300、500、1000 三个池上 ICIR 的最小值。一个在所有池上都有效的公式，比只在某一个池上极强的公式可靠得多。
- **分年稳定性**：适应度里扣掉「IC 为负的年份数」。
- **参数扰动**：入选公式的窗口参数 ±20% 后 IC 不能崩。窗口 13 有效、12 和 14 都无效的公式，大概率是噪声。
- **控制膨胀**：长度惩罚、限制最大树深，加上 hoist 变异（把子树提升上来，缩短公式）。

### 3.4 工程：GP 的瓶颈在评估，不在进化

一代 2000 个个体、每个都要在「全市场 × 十年日频」的面板上算一遍，这才是真正的算力瓶颈。常见的优化手段：

- **向量化面板计算**：把整个面板放进 GPU 张量（PyTorch）或 Polars，一个算子一次处理全部股票和全部日期。
- **子表达式缓存**：以规范化后的子树字符串为 key，缓存中间结果。GP 的子树高度重复，命中率很高。
- **代理评估**：先在一小段时间、股票子集上评估，只有前 10% 的个体才做全样本评估。

### 3.5 代表工作（供检索）

- **AutoAlpha**（Zhang et al., 2020）：分层进化，加上基于 PCA 的多样性控制，防止种群塌缩到同一个信号。
- **AlphaEvolve**（Cui et al., SIGMOD 2021）：把因子表示成带参数的计算图，而不只是公式树。注意：它和 DeepMind 2025 年的同名工作（LLM 引导的程序进化）不是一回事，后者见 §9.4。

## 4. 强化学习 / 树搜索：把「写公式」当作序列生成

**依赖基础因子库：依赖语法（②）；Alpha101 可以作为初始因子池参与奖励计算（③），也可以作为预训练示范数据。**

这一类对你来说应该最亲切：**本质上就是一个「解码器生成 token 序列，用环境奖励做策略梯度」的问题**，和 RLHF 很像，只是奖励来自回测。

### 4.1 问题建模（以 AlphaGen 为例）

AlphaGen（Yu et al., KDD 2023）是这个方向的标志性工作：

| RL 要素 | 定义 |
| --- | --- |
| 公式表示 | **逆波兰表达式（RPN）** 的 token 序列，例如 `close 10 ts_mean volume corr`。它天然就是一个栈式的序列生成问题 |
| 词表 | 字段、算子、窗口常数、数值常数、结束符 |
| 状态 | 已经生成的部分 token 序列 |
| 动作 | 下一个 token。用**合法性掩码**屏蔽掉当前栈状态下非法的 token（比如栈里只有一个操作数时不能选二元算子） |
| 奖励 | 只在序列结束时给出：**把这个新公式加入因子池后，池子线性组合的 IC 提升了多少** |
| 策略 | 原论文是 LSTM + PPO |

### 4.2 最关键的设计：奖励看「池子协同」，不看单因子

```text
维护一个容量为 K 的因子池 P = {f_1, ..., f_K}（初始可以直接放入 Alpha101 里最好的一批）
生成新公式 f_new：
    P' = P ∪ {f_new}
    在训练段上拟合线性组合权重 w = argmin ‖Σ w_i f_i − y‖（或直接最大化组合 IC）
    reward = IC(Σ w_i f_i on P') − IC(on P)
    如果 |P'| > K：去掉权重绝对值最小的因子
```

这样的奖励自动惩罚了冗余：一个和池内已有因子高度相关的新公式，即使单独 IC 很高，边际贡献也接近 0。
这比「单因子 IC + 相关性惩罚」更优雅，因为它直接优化最终要用的东西，也就是组合后的信号。

把 Alpha101 放进初始池，就等于把角色 ③（「必须对 Alpha101 有增量」）直接写进了奖励函数。

### 4.3 你熟悉的技术在这里的对应

- **策略网络**：可以换成小型 Transformer 解码器。公式长度一般不超过 20–30 个 token，模型不需要大。
- **监督预训练**：先在 Alpha101 的 RPN 序列（加上 §2 模板枚举出来的合法公式）上做行为克隆，再做 RL 微调。和「先 SFT 再 RL」是同一个套路，能显著减少早期生成的非法或无意义公式。
- **奖励很稀疏、噪声很大**：需要奖励归一化、熵正则防止模式塌缩，还要把相同的公式去重缓存。
- **评估太贵**：一次奖励等于一次面板回测加一次组合拟合。可以训练一个**代理模型**（输入公式，预测它的 IC），先用代理模型筛，只对有希望的公式做真回测。这就是 AlphaForge 一类「生成器 + 预测器」框架的思路。

### 4.4 变体（供检索）

- **MCTS 类**：用蒙特卡洛树搜索代替策略梯度，在公式空间里做有向搜索，可以配合风险偏好型的选择策略。
- **GFlowNet 类**：目标是「按奖励大小成比例地采样」，天然能产生更多样的公式，而不是塌缩到一个最优解。
- **AlphaForge**（2024）：生成器负责产生公式，预测器负责给公式打分，再按时间动态调整因子组合的权重。

### 4.5 和遗传规划比

| 维度 | 遗传规划 | RL / 搜索 |
| --- | --- | --- |
| 搜索的「记忆」 | 没有：只靠种群传递 | 有：策略网络会学到「什么样的结构容易好」 |
| 冗余控制 | 需要额外设计 | 奖励设计自带（池子协同） |
| 工程复杂度 | 低 | 中高 |
| 稳定性 | 跑多次结果差别大 | 训练本身也不稳定，需要调参 |

## 5. 机器学习合成：把因子库当特征

**依赖基础因子库：强依赖。Alpha101 的 101 个因子值就是特征（角色 ①）。**

这是业内**最主流的 ML 用法**。它不「挖」新公式，而是学习一个非线性函数，把已有因子合成为一个更强的打分。
这个打分本身就被当作一个新因子，走同样的测试和入库流程。

### 5.1 问题定义

```text
X_{i,t} = [alpha_1(i,t), ..., alpha_101(i,t), 行业 one-hot, log 市值, ...]
y_{i,t} = 股票 i 从 t+1 到 t+1+h 的收益，经过加工（见 5.3）
学习 g：X → 打分，使得每天截面上的 RankIC(g(X_t), y_t) 最大
```

### 5.2 特征预处理（每天截面上做）

1. **缺失值**：用截面中位数或行业中位数填补，同时加一个「是否缺失」标记。
2. **去极值**：MAD 或分位数截断。
3. **标准化**：截面 rank 后映射到正态分布（rank-gauss）。这比 z-score 更鲁棒，对树模型影响不大，但对神经网络很重要。
4. **只能用截面统计量**：**绝对不能用全样本的均值和方差做标准化**，否则就引入了未来信息。

### 5.3 标签工程：比模型选择更重要

| 标签设计 | 做法 | 目的 |
| --- | --- | --- |
| 起点 | 从 t+1 开盘价或 t+1 的 VWAP 开始算 | A 股是 T+1 交易，t 日收盘的信号最早只能在 t+1 成交 |
| 窗口 h | 1、5、10、20 日 | 应该和换手能力、调仓频率匹配。Alpha101 类信号适合短的 h |
| 超额 | 减去当天截面均值，或减去基准收益 | 去掉市场整体涨跌 |
| 中性化 | 对行业和风格因子做截面回归后取残差 | 让模型学「纯 alpha」，而不是重新学一遍行业和市值暴露 |
| 排序化 | 截面 rank 或 rank-gauss | 降低极端收益的影响，也和评价指标 RankIC 更一致 |
| 可交易性掩码 | 剔除 t+1 一字涨停（买不进）、停牌、ST、上市不满 N 天 | 否则模型会学到你根本吃不到的收益 |

### 5.4 模型与损失函数

- **主力**：LightGBM / XGBoost。在表格型、低信噪比、特征高度共线的场景下又稳又快。
- **基线**：等权合成、ICIR 加权、Ridge。**任何 ML 模型都必须先打赢等权合成**，否则就没有意义。
- **损失函数**：
  - 回归（MSE / Huber）：最简单，但和排序目标有错位。
  - 排序（LambdaRank）：把每一天当作一个 query group，直接优化排序。
  - 自定义 IC 损失：每天截面上的负 Pearson 相关，需要可微的实现，神经网络里用得多。

### 5.5 验证方法：金融时间序列的特殊处理

- **只能按时间切分**：训练、验证、测试严格按时间先后。
- **Purge + Embargo**：如果标签窗口是 h 天，训练集最后 h 天的标签会和验证集在时间上重叠，必须删掉（purge），并在两段之间留出间隔（embargo）。这是 López de Prado 提出的方法，也是金融 ML 和普通 ML 差别最大的地方之一。
- **滚动重训**：每月或每季度用最近 N 年的数据重训一次（walk-forward），模拟真实的上线过程。
- **多随机种子集成**：低信噪比下，不同种子训练出来的模型差异很大，用 5–10 个种子取平均。

### 5.6 从模型里「读出」新因子（ML → 人工的闭环）

ML 模型本身是黑箱，但可以从中提取可解释的新因子：

1. 算 **SHAP 交互值**，找出交互最强的因子对，比如「Alpha#6（量价相关）× 市值」。
2. 画出这对因子的部分依赖图，看交互的具体形状（比如在小盘股里是负相关，大盘股里是正相关）。
3. 把这个形状写成显式的条件因子，回到 §1.4，作为新的人工因子入库。

### 5.7 ML 在「筛选」上的用法

ML 除了做合成，也可以直接用来**选因子**：

- **Lasso 路径 / 稳定性选择**：在不同的时间子样本上反复跑 Lasso，保留被选中频率最高的因子。
- **条件 IC**：用树模型看一个因子在哪些子集上有效，从而发现它的「适用域」。

### 5.8 常见的坑

- Alpha101 内部有不少高度相关的因子，树模型会在它们之间随机选分裂点，所以**特征重要性不稳定，不要过度解读**。
- 合成因子的换手往往比单因子高得多，需要对输出做平滑，或者在标签里加入换手的考量。
- 训练集上的 IC 在低信噪比下几乎没有参考价值，只看验证集和测试集。

## 6. 深度学习端到端：从原始数据直接学因子

**依赖基础因子库：不依赖。** 只用原始量价序列就能训练。Alpha101 可以作为附加输入，更有意思的用法是**把 Alpha101 的算子做成网络层**（见 6.2）。

这是近几年量价 alpha 的主要来源之一，也是你的 Transformer 和 TSFM 经验最能派上用场的地方。

### 6.1 输入表示

| 表示方式 | 形状 | 说明 |
| --- | --- | --- |
| 个股时序窗口 | `[N, T, F]`，例如过去 60 天 × 6 个字段 | Qlib 的 Alpha360 就是这种：60 天 × 6 个字段，用最后一天的收盘价归一化 |
| 手工特征 + 时序 | `[N, T, F']` | 例如 Qlib 的 Alpha158（158 个手工量价特征）再加上时序维度 |
| 分钟 bar | `[N, 240 × D, F]` | 日内结构，数据量大一到两个数量级 |
| 订单簿快照 | `[N, T, levels × 4]` | 高频方向，见 §7 |

价格序列必须做**窗口内归一化**（除以窗口最后一天的收盘价，或取对数收益），否则不同股票的价格尺度差几百倍。

### 6.2 AlphaNet：Alpha101 和深度学习的桥梁

华泰金工 2020 年提出的 AlphaNet 值得单独讲，因为它**把 Alpha101 的算子当成了卷积核**：

```text
输入：「数据图片」 [F=9, T=30]
      F = open, high, low, close, vwap, volume, return, turn, free_turn
                │
                ▼
特征提取层（不带可学习参数，本质上就是 Alpha101 的算子）：
      ts_corr(X_i, X_j, d)、ts_cov(X_i, X_j, d)   ← 对所有字段两两组合
      ts_stddev(X_i, d)、ts_zscore(X_i, d)、ts_return(X_i, d)、ts_decaylinear(X_i, d)
      在时间维上按步长 d 滑动，类似步长为 d 的一维卷积
                │
                ▼
BatchNorm → 池化（均值、最大、最小）→ 展平 → 全连接或 GRU → 预测未来收益
```

它的思路是：人工因子本质上是「字段两两组合 × 固定的时序算子」，那就把所有组合都算出来，让网络学习怎么加权和非线性组合。
在此基础上可以再进一步：把固定算子换成**可学习的参数化算子**（比如可学习的衰减权重），就过渡到了纯深度学习。

**这是 Alpha101 在深度学习路线里最自然的用法：不是把它的输出当特征，而是把它的算子当归纳偏置。**

### 6.3 架构谱系

| 架构 | 核心思想 | 代表工作（供检索） |
| --- | --- | --- |
| RNN / GRU / LSTM | 按个股建模时序 | Qlib 的基线模型 |
| 时序 Transformer | 个股时序上的自注意力 | — |
| **时序 + 截面双重注意力** | 先在每只股票内部沿时间做注意力，再在同一天的股票之间做注意力，捕捉行业联动和领先滞后关系 | MASTER（AAAI 2024，市场信息引导的股票 Transformer） |
| 图神经网络 | 在行业、概念、供应链关系图上传播信息 | HIST（利用概念板块的共享信息） |
| 应对分布漂移 | 多个预测头 + 路由，或者元学习做增量适配 | TRA、DoubleAdapt |
| 潜因子生成模型 | 把因子当成隐变量，预测收益的分布而不只是点估计 | FactorVAE（AAAI 2022） |

截面注意力是这个领域相对 NLP 最特殊的地方：**同一天的 N 只股票组成一个「集合」，模型需要看到整个集合才能排序**。
这很像 set transformer，而不是逐个样本独立预测。

### 6.4 量化特有的训练细节

| 环节 | 做法 | 为什么 |
| --- | --- | --- |
| Batch 构成 | **一个 batch = 一个交易日的全部股票**（或其中一大块） | 损失函数和评价指标都是截面上的，打乱不同日期的样本会破坏截面结构 |
| 损失 | 每天截面的负 IC（可微的 Pearson），或 listwise 排序损失 | 直接对齐评价指标 |
| 标签 | 截面 rank-gauss 后的超额收益 | 同 §5.3 |
| 早停 | 按验证集的**日均 IC**，而不是验证集的 loss | loss 和 IC 在低信噪比下经常不一致 |
| 集成 | 多种子、多窗口平均 | 单个模型的方差非常大 |
| 重训 | 按月或按季滚动 | 应对非平稳 |
| 后处理 | 对输出做行业和市值中性化，再做平滑 | 去掉无意中学到的风格暴露，控制换手 |

```python
# 截面 IC 损失（一个 batch 就是一个交易日）
def ic_loss(pred: Tensor, target: Tensor) -> Tensor:
    # pred, target: [N]，同一天的 N 只股票
    p = pred - pred.mean()
    t = target - target.mean()
    return -(p * t).sum() / (p.norm() * t.norm() + 1e-8)
```

### 6.5 TSFM 的视角：为什么直接用效果不好，以及怎样用才对

你有 TSFM 微调经验，这一节专门讲这个。

**直接拿通用 TSFM（Chronos、TimesFM、Moirai、Timer 等）预测个股收益，效果通常很差。原因有三个：**

1. **目标错配**：TSFM 学的是点预测或分布预测（MSE、分位数损失），而因子要的是**截面排序**。一个在 MSE 上几乎等于预测 0 的模型，IC 也几乎是 0。
2. **可预测性极低**：日收益接近白噪声。TSFM 在电力、交通、气象这类有强周期和强自相关的语料上预训练，学到的归纳偏置（季节性、趋势外推）在收益序列上几乎没有用武之地。
3. **缺少截面信息**：TSFM 逐条序列独立建模，看不到「同一天其他股票在干什么」，而截面的相对信息恰恰是因子的核心。

**更可行的用法：**

| 用法 | 做法 | 说明 |
| --- | --- | --- |
| **(a) 编码器 + 截面头** | 冻结或 LoRA 微调 TSFM 的编码器，把每只股票的历史窗口编码成一个 embedding，再接一个截面模型（截面注意力或 MLP），用截面 IC 损失训练 | TSFM 只负责「表示」，不负责「预测」。这是最稳妥的起点 |
| **(b) 金融领域继续预训练** | 在大量 K 线数据上继续预训练，或者直接用专门的金融时序基础模型（例如把 K 线 token 化后训练的 Kronos 一类工作），再微调排序头 | 预训练语料和下游任务的分布更接近 |
| **(c) 预测更好预测的东西** | 用 TSFM 预测**波动率、成交量、换手率**，而不是收益 | 这些序列的自相关和周期性很强，TSFM 表现好得多。预测出来的结果可以作为风险因子、流动性因子，或者作为 §5 模型的特征 |
| **(d) 意外因子** | 因子 = 实际值 − TSFM 的预测值，比如「实际成交量 − 预测成交量」 | 「意外」本身就是信息。异常放量是一个经典的信号来源，TSFM 给出了一个比简单移动平均更好的「预期」 |

**微调时的额外注意事项：**

- **数据泄露**：归一化统计量只能用窗口内或截面内的数据；验证集的股票和时间段必须和训练集严格隔离。如果基础模型的预训练语料里包含了你回测期的金融数据，也算一种泄露。
- **有效样本量**：见 §0.1。十年数据，真正独立的样本大约是两千多个交易日，而不是几百万行。大模型在这个量级上非常容易过拟合，LoRA 的秩和训练步数都要保守。
- **评价**：不要看验证集的 MSE，只看日均 RankIC、ICIR，以及分组回测的多空收益。

### 6.6 优缺点

- 优点：能发现人工写不出来的非线性模式；在量价、高频方向上是目前 alpha 的主要来源之一。
- 缺点：黑箱、衰减快、训练方差大、需要持续重训；有效的 alpha 需要大量工程细节支撑，论文里的结果往往难以复现。

## 7. 高频与微观结构因子：「高频因子低频化」

**依赖基础因子库：不依赖。** 数据源不同（分钟 bar、逐笔成交、订单簿），但 Alpha101 的很多思想可以直接平移到日内。

### 7.1 思路

用日内的高频数据刻画一只股票当天的交易行为，**聚合成一个日度数值**，再作为日频、周频因子用于截面选股。
这就是国内金工常说的「高频因子低频化」，也是这个平台里 Level2 族的来源。

### 7.2 典型因子家族

| 家族 | 例子 | 含义 |
| --- | --- | --- |
| 日内收益分布 | 已实现偏度、峰度、上行和下行波动的比值 | 彩票偏好、尾部风险 |
| **日内量价相关** | 分钟级 `corr(价格变化, 成交量)` 的日均值 | **Alpha#6 这类量价相关因子的日内版本** |
| 资金流 | 主动买入减主动卖出、大单净流入 | 知情交易者的痕迹 |
| 订单簿 | 订单流不平衡（OFI）、盘口价差、挂单深度 | 短期供需 |
| 时段效应 | 开盘 30 分钟和尾盘 30 分钟的收益、成交占比 | 不同类型的投资者在不同时段活跃 |
| 知情交易 | VPIN 等 | 成交中知情交易的比例 |
| 流动性 | 分钟版 Amihud、Kyle's λ | 价格冲击成本 |

### 7.3 以 Alpha101 为起点怎么做

1. 把 Alpha101 的公式中的「日」换成「分钟 bar」，在每个交易日内部计算，得到一个日内序列。
2. 用均值、尾部分位数、稳定性（标准差）等方式把日内序列聚合成一个日度数值。
3. 再做 N 日平滑，进入正常的截面测试。

例如 Alpha#6 `-corr(open, volume, 10)` 的日内版本：每个交易日内部，计算 240 根分钟 bar 上价格和成交量的相关系数，得到一个日度值，再取 20 日均值。

### 7.4 挖掘方法

- 人工设计（主流）。
- 在分钟级算子上跑遗传规划（和 §3 一样，只是面板多了一个日内维度）。
- 深度学习：直接在订单簿快照上训练卷积或 Transformer 模型，比如 DeepLOB 一类工作。

### 7.5 工程要点

数据量是日频的几百倍（TB 级），需要列式存储、按日期分区、并行计算。和 Alpha101 的日频基础设施基本是两套系统，要提前规划。

## 8. 另类数据与 NLP 因子

**依赖基础因子库：不依赖。** 信息来源完全是文本或其他另类数据。

### 8.1 数据源

| 类别 | 例子 |
| --- | --- |
| 卖方研究 | 研报文本、评级和目标价的调整、盈利预测修正 |
| 公司信息披露 | 公告、年报的管理层讨论、交易所互动平台的问答、业绩说明会纪要 |
| 新闻和舆情 | 财经新闻、股吧和社交媒体 |
| 其他另类 | 供应链关系、招聘信息、专利、卫星图像、App 数据 |

### 8.2 方法演进

| 阶段 | 做法 | 特点 |
| --- | --- | --- |
| 词典法 | 用金融情感词典统计正负面词频 | 简单、可解释，但太粗糙 |
| 监督微调 | 微调 BERT 或 FinBERT，标签用「公告后 N 天的超额收益方向」 | 直接学「市场怎么反应」，而不只是「文字是正是负」 |
| LLM 零样本打分 | 让大模型按若干维度给文本打分（这个平台的行业研报五视角打分就是这种） | 不需要标注数据，但打分口径不稳定 |
| **LLM embedding + 下游模型** | 用大模型把文本编码成向量，作为特征喂给 §5 的模型，由模型学习 embedding 和收益的关系 | 目前比较主流的做法，把「理解文本」和「预测收益」分开 |

### 8.3 关键细节

- **时间点对齐**：必须精确到文本**发布的时刻**。盘中发布的信息，当天收盘价里可能已经反映了一部分；盘后发布的，只能从第二天开盘开始算。
- **覆盖稀疏**：很多股票在某一天没有任何新闻或研报，截面上大量缺失。通常只在有覆盖的股票子集内部做排序，或者设计成事件驱动型的因子（只在事件发生后持有一段时间）。
- **和量价因子结合**：一个经典发现是，有新闻驱动的价格变动倾向于延续，没有新闻的价格变动倾向于反转。所以文本信号最有用的地方之一，是去**给 Alpha101 的反转因子做条件化**（回到 §1.4）。

### 8.4 LLM 的前视偏差：最大的坑

**大模型的预训练语料里包含了回测期间发生的事。**
例如用一个知识截止到 2024 年的模型，去给 2021 年的研报打分，它可能「知道」这家公司后来怎么样了。
这会让回测结果虚高，而且极难察觉。

应对办法：

- 只在模型知识截止日期**之后**的样本上做真正的验证。
- 把文本里的公司名、股票代码、日期匿名化，减少模型「认出来」的可能。
- 优先使用「只做编码、不做判断」的用法（上面的 embedding 方案），它比让模型直接打分受前视偏差影响小一些，但也不能完全避免。

## 9. LLM 智能体驱动的因子挖掘

**依赖基础因子库：依赖语法（②），Alpha101 作为少样本示例；也可以完全从经济假设出发。**

这是最近两三年最活跃的方向。本质上是**用 LLM 替代人工研究员，自动走完 §1 的「假设 → 公式 → 验证 → 反思」循环**。

### 9.1 典型架构

```text
   ┌─────────────────────────────────────────────────────────────────┐
   │                        知识库（RAG 记忆）                         │
   │  已有因子（Alpha101 …）· 每次尝试的假设、公式、指标、失败原因      │
   └───────▲─────────────────────┬───────────────────────────────────┘
           │                     │ 检索相关的历史尝试
           │                     ▼
   ┌───────┴──────┐   ┌──────────────────┐   ┌──────────────┐   ┌──────────────────┐
   │ 反思 / 分析   │◄──│ 回测执行          │◄──│ 公式实现      │◄──│ 假设生成          │
   │ 为什么有效或  │   │ 统一的单因子测试  │   │ 写成 DSL 表达式│   │ 提出经济或行为     │
   │ 失败，下一步  │   │ + 增量检验        │   │ + 语法校验    │   │ 金融上的假设       │
   └──────────────┘   └──────────────────┘   └──────────────┘   └──────────────────┘
```

### 9.2 代表工作（供检索）

| 工作 | 要点 |
| --- | --- |
| Alpha-GPT（2023） | 人机协同：研究员用自然语言描述想法，LLM 负责转成公式并解读结果 |
| AlphaAgent（2025） | 专门对抗 alpha 衰减：用**原创性约束**（和已有因子库的 AST 相似度）、**假设和公式的一致性检查**、**复杂度控制**三个正则项，逼 LLM 产出新颖且有逻辑的因子 |
| RD-Agent(Q)（微软，2025） | 把因子挖掘和模型开发放在同一个研发循环里协同迭代，是一个开源的完整框架 |

### 9.3 Alpha101 在这里怎么用

1. **少样本示例**：在提示词里给出若干个 Alpha101 公式及其经济解释，让 LLM 学会 DSL 的写法和「一个好因子长什么样」。
2. **语法约束**：把 Alpha101 的字段和算子整理成一份 DSL 规范，LLM 的输出必须能被解析器接受，不合法就返回错误让它重写。
3. **原创性基准**：把 Alpha101 放进知识库，新公式和其中任何一个的 AST 相似度或因子值相关性过高，就直接打回。

特别要注意：Alpha101 是公开论文，**LLM 在预训练里大概率见过它**。如果不加原创性约束，它很容易「回忆」出 Alpha101 的原公式或微小变体，然后你会以为自己挖到了新因子。

### 9.4 LLM 引导的进化：GP 和 LLM 的结合

还有一条很有前景的路：**保留遗传规划的进化框架，但把交叉和变异交给 LLM 来做**。

- 传统 GP 的变异是随机替换一个节点，大部分变异是无意义的。
- 让 LLM 做变异：给它两个父代公式和它们的指标，让它「解释为什么这个好、那个差，然后提出一个改进版本」。
- 这和 DeepMind 的 FunSearch（Nature 2023）和 AlphaEvolve（2025）是同一个思路：**LLM 负责提出有语义的改动，进化框架负责选择和保留**。

### 9.5 实现要点

- **DSL 和解析器是地基**：没有一个严格的表达式语言和校验器，LLM 的输出没法自动执行。
- **评估要并行、要缓存**：智能体一天可以提出上千个候选，回测引擎必须跟得上。
- **把失败记下来**：知识库里记录失败的尝试及原因，比记录成功的更重要，否则智能体会反复犯同样的错。
- **预算控制**：LLM 调用和回测都要花钱，需要设定每轮的候选上限和早停规则。
- **多重检验**：智能体尝试的次数远多于人工，§11.2 的问题会被放大。

### 9.6 和 GP、RL 的比较

| 维度 | GP / RL | LLM 智能体 |
| --- | --- | --- |
| 先验知识 | 没有，纯搜索 | 有：模型知道金融学和已有的因子 |
| 搜索效率 | 低，大部分候选没意义 | 高，候选大多「讲得通」 |
| 可解释性 | 公式可能很怪 | 每个公式都附带假设 |
| 多样性 | 高 | 受限于模型先验，容易扎堆在「常见思路」附近 |
| 主要风险 | 过拟合 | 回忆已知因子、前视偏差 |

## 10. 统计 / 潜在因子（补充）

**依赖基础因子库：不依赖。** 直接从收益的协方差结构里提取因子。这一类更多用于风险模型和构造标签，而不是直接当 alpha，但在因子体系里不可或缺。

| 方法 | 做法 | 用途 |
| --- | --- | --- |
| PCA 统计因子 | 对收益矩阵做主成分分析，前几个主成分就是统计意义上的「市场因子」 | 风险模型、行业和风格之外的隐藏共同运动 |
| **残差反转** | 收益减去对 PCA 因子（或行业 ETF）的暴露后得到残差，残差偏离过大时押注它回归 | 统计套利的经典做法（Avellaneda & Lee, 2010） |
| IPCA | 因子暴露是股票特征（比如 Alpha101 的值）的线性函数，同时估计因子和暴露 | 把「特征」和「风险因子」统一在一个模型里 |
| 条件自编码器 | 用神经网络把股票特征映射成因子暴露（Gu, Kelly & Xiu, 2021） | IPCA 的非线性版本 |

和 Alpha101 的关系：统计因子可以作为**中性化的对象**。
§5.3 的标签中性化、§3.2 的残差适应度，都可以用「行业 + 风格 + 前 k 个统计因子」做回归取残差，确保挖到的是真正独立的 alpha。

### 11.1 横向对比

| 方法 | 依赖基础因子库 | 产出 | 可解释性 | 算力 | 过拟合风险 | 典型频率 | 衰减 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| §1 人工研究 | 强 | 公式 | 高 | 低 | 中 | 日 / 周 / 月 | 慢 |
| §2 模板枚举 | 语法 | 公式 | 高 | 中 | 中高 | 日 / 周 | 中 |
| §3 遗传规划 | 语法 / 叶子 | 公式 | 中 | 高 | 高 | 日 / 周 | 中快 |
| §4 RL / 搜索 | 语法 / 因子池 | 公式 | 中 | 高 | 高 | 日 / 周 | 中快 |
| §5 ML 合成 | 强（特征） | 模型打分 | 低（可用 SHAP 部分解释） | 中 | 中 | 日 / 周 | 中 |
| §6 深度学习 | 不依赖 | 模型打分 | 低 | 很高 | 高 | 日内 / 日 | 快 |
| §7 高频 | 不依赖 | 公式或模型 | 中 | 很高（数据） | 中 | 日内 → 日 / 周 | 快 |
| §8 另类 / NLP | 不依赖 | 文本信号 | 中 | 中高 | 中（前视偏差高） | 事件驱动 | 中 |
| §9 LLM 智能体 | 语法 + 示例 | 公式 + 假设 | 高 | 中高（按调用计费） | 中高 | 日 / 周 / 月 | 中 |
| §10 统计因子 | 不依赖 | 隐变量 / 残差 | 低 | 低 | 低 | 日 | — |

### 11.2 多重检验：挖得越多，越要严格

如果你测试了 1000 个候选因子，即使它们全是噪声，按 p < 0.05 也会有大约 50 个「显著」。所有自动化方法都会把这个问题放大几个数量级。

- **记账**：记录每一个被测试过的候选，而不只是入选的那些。「试了多少次」是评估结果可信度的必要信息。
- **提高门槛**：Harvey, Liu & Zhu（2016）认为，考虑到学术界已经测试过的因子数量，新因子的 t 值至少要超过 3.0，而不是传统的 2.0。
- **修正后的夏普比率**：Bailey & López de Prado 的 Deflated Sharpe Ratio，根据尝试次数修正夏普比率的显著性。
- **真正的样本外**：留出一段**从未被任何挖掘过程碰过**的时间段，只在最后验收时用一次。

### 11.3 增量检验：新因子必须对已有因子库有贡献

两种标准做法：

```text
做法 1（截面回归）：
    每天把新因子对 [Alpha101 全部因子 + 行业 + 风格] 做截面回归，取残差
    对残差做单因子测试。残差的 IC 仍然显著，才算有增量。

做法 2（组合层面）：
    在已有因子库的合成模型上加入新因子，看合成信号的测试集 IC 或组合超额是否显著提升。
```

### 11.4 可交易性检验

- **换手和成本**：Alpha101 类的短周期因子换手很高，扣除双边千分之二到千分之三的成本后，很多因子的超额会大幅缩水甚至消失。
- **涨跌停和停牌**：A 股一字涨停买不进、一字跌停卖不出，回测必须处理。
- **容量**：在小盘股上有效的因子，资金规模一大，冲击成本就会吃掉收益。
- **拥挤度**：跟踪因子的换手、多空两端的估值差等指标，判断它是否已经被很多人在交易。

### 11.5 衰减监控

入库不是终点。对每个在用的因子持续跟踪滚动 IC、分年表现、和其他因子的相关性变化，
设定明确的「降权」和「下线」规则。

## 12. 以 Alpha101 为起点的推荐路线

结合[平台业务架构报告 §9](platform_business_architecture.md) 的分期路线，建议按以下顺序推进：

| 阶段 | 方法 | 要做的事 | 产出 |
| --- | --- | --- | --- |
| 1 | §0.3 漏斗 + §1 人工 | 复现 Alpha101；搭好单因子测试、增量检验、可交易性检验；把 101 个公式按语义单元归类 | 一张「Alpha101 在 A 股各股票池上的表现」基准表 |
| 2 | §1 因子工厂 + §2 模板枚举 | 从 Alpha101 抽取模板；用换手率、成交额等 A 股特有字段填槽；按族去相关、限额 | 第一批「对 Alpha101 有增量」的因子 |
| 3 | §5 ML 合成 | 以 Alpha101 + 第 2 阶段的新因子为特征，LightGBM + purged 滚动验证，打赢等权合成 | 合成因子，接入组合优化 |
| 4 | §3 GP 或 §4 RL | 用残差适应度（或池子协同奖励）挖新结构，多轮挖掘 | 公式型新因子 |
| 5 | §6 深度学习（发挥你的强项） | AlphaNet 式网络起步，再尝试截面注意力模型、TSFM 编码器加截面头 | 端到端量价因子 |
| 6 | §9 LLM 智能体 | 在前面搭好的 DSL、回测引擎和结果库之上，加一个假设生成、反思的循环 | 自动化因子研发流水线 |
| 可选 | §7 高频、§8 NLP | 需要新的数据源和基础设施，按资源情况决定 | — |

排序的逻辑是：**先把漏斗（评估体系）建扎实，再扩大漏斗的入口**。
入口越自动化，漏斗越重要。没有严格的增量检验和多重检验控制，挖得越多，自己骗自己的概率就越大。

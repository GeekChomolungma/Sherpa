§5、§6，这里不重复。

## 1. 现状：手工 alpha + regime 切片的研究方式

现在一个自定义 alpha 的研究路径是：

```text
手写公式 compute()  ──>  阶段一：按 regime state 切片算条件 IC  ──>  汇总报告 04 矩阵（每个 state 的 Top-K）
     ──>  关卡2：L2 路由，每个 state 用自己的名单和方向（IC 符号）  ──>  关卡3：扣费回测
```

以 `quote_activity_rank`（窗口成交额的截面排名）为例：阶段一在 trend 的 bear / neutral / bull 三个 state 上
分别统计 IC，如果牛市 IC 为负、熊市 IC 为正，关卡2 的 L2-trend 路由配方就会"牛市做多活跃币、熊市做空活跃币"。
这套方式能跑通，但有几个结构性问题。

### 1.1 痛点

| # | 痛点 | 具体表现 |
| --- | --- | --- |
| P1 | **状态划分是人定的** | 4 个维度 × 3 档，档位边界（滚动分位数）、回看窗口（120 根）都是人工设定。换一套边界，结论可能就变了 |
| P2 | **只能看单个维度，表达不了交互** | 四维组合 `regime_label` 有几十种，每种样本太少，所以关卡2 只能按一个维度路由。"牛市 **且** 流动性高时放量才有效"这种条件表达不出来 |
| P3 | **方向是硬切换** | 权重只能是 ±1，state 一变，方向整体翻转。state 边界附近来回跳，仓位也跟着来回翻，产生额外换手；regime 还在 warm-up 期（NA）时只能退回 fallback |
| P4 | **切片后样本少、检验次数多** | 每个 state 只有一部分 bar，小 state 经常 `low_sample`；因子数 × state 数的检验次数一多，靠运气通过显著性门槛的因子也多 |
| P5 | **先有故事、再去验证（经验偏置）** | "牛市放量是热情、熊市放量是恐慌出逃"是先有的经验，再按这个经验去切片、去找支持它的数字。研究者可以反复换维度、换边界、换窗口，直到看到想要的结果——这是确认偏误，也是"研究者自由度"带来的隐性过拟合 |
| P6 | **线上难维护** | 每个因子 × 每个 state 的方向表要人工维护；什么时候重估方向、用多长的历史重估，没有统一机制。实盘时 regime 刚切换的那几根 bar 怎么处理，也要另写规则 |

P1–P3 是**表达能力**的问题，P4–P5 是**统计可信度**的问题，P6 是**工程落地**的问题。

### 1.2 用机器学习模型能改善什么

把"选因子、定方向、按状态切换"这几步合并成一个模型：输入是每个 symbol 当期的一组特征（原始量价衍生量、
现有 alpha 分值、市场状态变量），输出是一个截面打分；训练目标直接对齐我们的评价指标（逐期截面 RankIC）。

| 痛点 | 模型方式下的对应 |
| --- | --- |
| P1 状态人定 | 市场状态以**连续变量**输入（大盘趋势强度、波动率分位数……），模型自己学在哪里分界，不需要人设档位 |
| P2 无交互 | 树模型和神经网络天然学"特征 × 状态"的交互，多个维度可以同时参与 |
| P3 硬切换 | 输出是连续打分，方向随状态**渐变**，不会在边界上整体翻转 |
| P4 样本碎片化 | 不切片，全部样本一起训练，状态只是其中几个特征 |
| P5 经验偏置 | 不预设"哪个状态下方向相反"，由数据决定。但偏置不会消失，只是转移到别处，见 §6 |
| P6 线上维护 | 方向、权重都包含在模型里；更新方式统一为"按固定节奏滚动重训"，回测和实盘用同一套机制（§7） |

在 alpha 层面，**模型输出就是一个普通的 alpha**：`compute(panel)` 返回 `(T, N)` 打分，照常走阶段一 → 关卡1/2
透传 → 关卡3。关卡2 透传后只剩一个权重为 +1 的单因子配方，也就是"权重恒为 1"，不再需要人工决定符号。

## 2. 总体流程

```text
                         ┌──────────────── 离线（research/ml_training/，可以依赖 lightgbm/torch）────────────────┐
BarPanel ──> 特征构建 ──> (T, N, K) 特征面板 ─┐                                                                 │
   │          (sherpa，训练和推断共用)         ├──> 滚动训练（每个重训时点 τ_j 训练一个模型）──> 模型文件 + 清单 manifest
   └──> 标签构建 ──> (T, N) 标签 ─────────────┘                                                                 │
                                                                                                                  │
                         ┌──────────────── 在线 / 研究流水线（sherpa，只做推断）─────────────────────────────────┘
BarPanel ──> 特征构建（同一个函数）──> MLAlpha.compute(panel)：每一行用"当时已经训练好的"那个模型推断 ──> (T, N) 打分
                                                    │
                                                    └──> 阶段一 → 汇总报告 → 关卡1/2 透传 → 关卡3（和其它 alpha 完全一样）
```

关键约定：

1. **训练和推断分开**。`MLAlpha.compute()` 只推断、不训练，模型在离线步骤里训练好、冻结成文件。这样阶段一
   （取选择段数据）和关卡3（取整个研究段数据）对同一根 bar 算出的打分完全一致。
2. **特征构建只有一份实现**，放在 sherpa 层，训练和推断都调用它。如果训练和推断各写一份，线上和回测的特征
   会悄悄对不上（同一原则见设计文档 §8.3 决策1：会改变决策结果的逻辑不允许回测、实盘各写一份）。
3. **每一行的打分只能来自训练截止早于它的模型**（point-in-time），见 §7.2。

### 2.1 数据形状

| 对象 | 形状 | 存储 |
| --- | --- | --- |
| 特征 | `(T, N, K)` | 长表：`MultiIndex(start_time, symbol)` × K 列（稀疏的币种上市/下架很多，长表比三维数组省空间，也直接喂得进 LightGBM） |
| 标签 | `(T, N)` | 同上，一列 |
| 预测（alpha 打分） | `(T, N)` | 宽表，跟 `panel.close` 对齐，也就是普通 alpha 的输出格式 |
| 训练样本 | 行 = (t, symbol) | 只保留**可流通性掩码为真、标签非空**的行 |

### 2.2 特征（第一版）

| 组 | 内容 | 预处理 |
| --- | --- | --- |
| A. 原始字段衍生 | 多窗口收益（1/6/42 根）、波动率、振幅 `(high−low)/close`、`log(quote_volume)` 的窗口均值和相对变化、taker 买入占比、成交笔数、OI 变化率 | 每期**截面** rank-gauss |
| B. 现有 alpha 分值 | 世坤因子、`custom` 因子（按 registry 的 qualified_name 列出） | 每期截面 rank-gauss |
| C. 市场状态变量 | `sherpa.metrics.regime` 里已经算出、但 `build_regime_report()` 目前没有返回的连续量：`market_breadth`、`benchmark_trend_up`、`market_rv`/`rv_quantile`、`dispersion_quantile`、`volume_quantile`、`taker_buy_ratio` | 本身是时序滚动分位数或比例，**不做截面处理**（同一期所有币取值相同） |
| D.（可选）离散 state | 四个维度的 state，one-hot | 仅用于消融对比（§5.2） |

特征清单写在一个 `FeatureSpec` 里（名字、参数、版本号），训练时写进模型清单，推断时校验一致。

### 2.3 标签

- **口径与研究配置一致**：`forward_returns(close, horizon=label.horizon_bars, delay=label.execution_delay_bars)`
  （`research/research_config.json`），不另定"后一天收益"。
- **掩码**：套和研究流水线同一个 `tradable_mask`，模型不学不可交易币的收益。
- **中性化（可选，默认开）**：对标签做 Beta/Size 截面回归取残差（`sherpa.risk.neutralize`），见 §5.5。
- **排序化**：每期截面 rank-gauss，降低极端收益的影响，也和 RankIC 目标一致。

### 2.4 模型

| 阶段 | 模型 | 目标 |
| --- | --- | --- |
| 第一版 | LightGBM | 回归（rank-gauss 标签上的 MSE）或 LambdaRank（每期一个 query group）。表格型、低信噪比、特征高度共线的场景下又稳又快，先用它建基线 |
| 第二版 | 神经网络（MLP → 截面注意力） | 可导的逐期 IC 损失（§5.1、§5.3） |

两版都用**多随机种子集成**（5 个种子取平均）；早停看内部验证段的**逐期 RankIC 均值**，不看 loss。

## 3. 代码落点

遵循"不预先创建、等有具体需求再建"的约定，只建第一版用得到的东西：

```text
sherpa/alpha/custom/ml/                 机器学习 alpha 主题（研究线按这个包路径挑因子）
    __init__.py
    features.py     FeatureSpec + build_features(panel, spec) -> 长表；训练和推断共用，只依赖 pandas/numpy
    labels.py       build_labels(panel, ...) -> 长表；只在训练时用，放这里是为了和特征共用预处理函数
    manifest.py     模型清单的读写与"按时间取模型"（纯 JSON，不依赖 ML 库）
    alpha.py        MLAlpha(CustomAlpha)：读清单、按行选模型、推断；lightgbm/torch 在加载模型时才 import
    models.py       具体注册的模型 alpha，比如 @register_alpha class LgbmV1(MLAlpha)

research/ml_training/                   离线训练（新的研究子目录，跟各关卡平级）
    run_training.py   按研究线配置做滚动训练，写模型文件和清单
    config.py         重训频率、训练窗口、超参数等
```

- `custom/__init__.py` 里 import `ml` 包，下游关卡才能按名字找到这些 alpha。
- **依赖**：`lightgbm`（第二版加 `torch`）放进 `pyproject.toml` 的 optional-dependencies `ml`，
  `pip install -e .[ml]`。`MLAlpha` 在第一次加载模型时才 import，没装 ML 库时 `import sherpa.alpha.custom` 不受影响。
- **模型文件不进 git**：默认存 `research/alpha_research/<研究线>/models/`，加进 `.gitignore`；清单 `manifest.json`
  体积小，可以进 git，方便复现和审计。
- **registry 无参实例化**：流水线用 `registry.get(name)()` 创建 alpha，不传参数。所以每个模型配置注册成一个
  子类（`LgbmV1`、`LgbmV1NoRegime` ……），用类属性写死特征清单和模型目录，而不是靠构造参数。

## 4. 训练流程（单次）

以重训时点 `τ` 为例：

1. 取 `τ` 之前的数据构建特征和标签（特征构建只用 `≤ t` 的数据，标签用 `t+delay … t+delay+horizon` 的收盘价）。
2. **Purge**：训练样本只取 `t ≤ τ − (horizon + delay)` 的行，保证每个训练标签在 `τ` 时刻都已经实现。
3. 训练窗口内部再切一个**内部验证段**（窗口最后 15%），两段之间同样留 `horizon + delay` 根 bar 的间隔。
   只用它做早停和少量超参选择。
4. 多种子训练，保存模型文件；在清单里追加一条：

```json
{
  "model_id": "lgbm_v1@2024-01-01",
  "feature_spec": "lgbm_v1/features@3",
  "train_rows_until": "2023-12-31T16:00:00Z",
  "valid_from": "2024-01-01T00:00:00Z",
  "valid_until": "2024-02-01T00:00:00Z",
  "seeds": [0, 1, 2, 3, 4],
  "inner_valid_ic": 0.041,
  "path": "models/lgbm_v1/2024-01-01/"
}
```

## 5. 需要改进的几处（设计决策）

### 5.1 RankIC 不可导

Spearman 相关要先排名，排名是离散操作，梯度为零，不能直接反向传播。处理方式：

- **第一版（LightGBM）绕开这个问题**：把标签先做截面 rank-gauss，再用 MSE 回归。对排序化的标签做回归，
  跟"最大化预测与排序化标签的 Pearson 相关"高度一致；或者用 LambdaRank（标签取每期的分位桶 0…q−1）。
- **第二版（神经网络）**：损失用**逐期 Pearson 相关**，标签是已经 rank-gauss 过的，所以效果接近 RankIC，而且
  处处可导。需要更贴近时再试可微排序（soft rank，Blondel et al. 2020）。
- **评估**始终用真正的 RankIC（`sherpa.metrics.factor.rank_ic`），和流水线口径一致。

### 5.2 状态变量是截面常数，只能通过交互起作用

同一期所有币的状态变量取值相同。逐期截面 IC 对"整体平移"不敏感，所以状态变量单独存在时**改变不了排序**，
只有和个股特征交互（"大盘趋势强时，成交活跃度的作用方向变了"）才有用。设计上：

- 用**树模型或带交互结构的网络**；线性模型学不到这种作用。
- 输入**连续状态变量**（§2.2 C 组），不只是离散 state，信息更多，也少一层人工分段。
- 做一个**消融实验**直接检验这件事：同一套配置跑"有状态变量"和"没有状态变量"两个模型，比较滚动样本外的
  IC。如果加了状态变量没有提升，说明"方向随状态变化"在数据里不成立，或者样本不够学出来——这个结论本身就
  很有价值，正好回答 §1 里经验偏置的问题。

### 5.3 损失函数的形式

- **只优化 −mean(IC) 的问题**：模型可能学成"少数时期 IC 很高、其余时期很差"。神经网络版用
  `−mean(IC) / std(IC)`（即 −IC_IR），或者 `−mean(IC) + λ·std(IC)`。
- **首尾更重要**：Top-K / Last-K 只交易两端，截面中间排得准不准对收益没有影响。可选做法：对标签两端加权，
  或者用 LambdaRank 这类更关注头部的目标（它只关注一端，做多和做空两侧可以各训一个，也可以只作为对照）。
- **换手成本**：损失里没有交易成本，输出可能每期剧烈跳动。两种手段：
  1. 训练时加惩罚项：相邻两期同一 symbol 预测值的排名差；
  2. 推断后做平滑（比如对打分做短窗口 EMA），平滑窗口当成一个超参，在关卡3 的扣费回测里一起看。

### 5.4 特征必须平稳化

原始价格水平不平稳，而且会让模型记住"哪个币是哪个币"（价格尺度本身就是身份标识）。所有个股特征都转成
收益率、比值或截面 rank-gauss；市场状态变量用已经是滚动分位数或比例的那几个。**所有标准化都只能用当期截面
或滚动过去窗口的统计量**，不能用全样本的均值和方差，否则就用到了未来信息。

### 5.5 标签口径与 Beta 暴露

逐期截面 IC 会消掉大盘整体涨跌，但消不掉"牛市里高 Beta 币涨得多"这种风格。模型如果只学到"牛市做多高 Beta
币"，那是风格押注，不是选币能力，在关卡3 里表现为一段时间很好、一换市况就回撤。所以：

- 标签默认先做 Beta/Size 中性化，模型学的是残差收益；
- 输出照常经过研究流水线的外层处理链（掩码 + 中性化），双重保险；
- 跑一版"标签不中性化"作为对照，看模型的收益有多少来自风格。

## 6. 经验偏置并没有消失，只是换了位置

不再人工切 regime、翻符号，确实去掉了最显眼的那部分人为决定。但下面几处仍然有偏置，而且更隐蔽：

| 偏置出现在哪 | 为什么危险 | 应对 |
| --- | --- | --- |
| **有效样本少** | 4h bar 有上万根，但完整的牛熊周期只有两三个。模型学"牛熊方向相反"时，真正独立的证据只有这几段，比人工切片更容易过拟合，而且看不出来 | 报告里按滚动折（fold）列出每个模型的样本外 IC，看是不是只靠某一两段；特征重要性和 SHAP 交互要在多个折之间稳定才可信 |
| **上游选择** | 选哪些特征、状态变量怎么定义、训练窗口多长、重训多频繁，都还是人定的 | 这些设置写进 `FeatureSpec` 和训练配置，带版本号；**只能根据选择段的样本外结果做决定**，验证段留给关卡2/3，holdout 只跑一次 |
| **反复试模型** | 试的配置越多，挑出来的最好那个越可能是运气 | 记录每一次试过的配置（清单里有），最终报告时说明一共试了几种；超参只在一个事先定好的小网格里选 |
| **规律不稳定** | 历史上学到的交互关系，未来可能失效 | 滚动重训（§7），并持续监控滚动样本外 IC；衰减到阈值以下时报警 |
| **低信噪比** | 截面 IC 通常只有 0.02–0.1，神经网络很容易拟合到噪声 | 先用 LightGBM 建基线，神经网络必须打赢它才用；多种子集成；早停看 IC 不看 loss |

**任何模型都必须先打赢简单基线**：最强单因子、世坤研究线的 G0 全局等权 / L1 ICIR 加权、手工的 L2 路由配方。
比较口径统一用关卡3 验证段的扣费净 Sharpe。

**把模型学到的东西读回来**：用 SHAP 交互值找交互最强的"特征 × 状态"组合，画部分依赖图。如果模型确实学到了
"牛市放量正向、熊市放量反向"，可以把它写成一个显式的条件因子回到手工因子库——这样经验是被数据验证过的，
而不是先入为主。

## 7. 与现有框架衔接，重点是滚动更新

### 7.1 滚动训练时间表

```text
research_start                    validation_start                 research_end           holdout_end
     │◄──────── 选择段 ────────────►│◄──────── 验证段 ───────────►│◄──── holdout ────►│
     │                               │                              │                    │
     │◄ 最短训练期 ►│τ1 │τ2 │τ3 │ … │τj │ …                          │ …                  │
                    模型1 服务 [τ1, τ2)，模型2 服务 [τ2, τ3) ……（每个模型只用 τ 之前 purge 过的数据训练）
```

| 参数 | 第一版取值（待确认） | 说明 |
| --- | --- | --- |
| 重训频率 | 每月（4h 周期约 180 根 bar） | 太频繁计算量大、模型抖动大；太稀疏跟不上市况变化 |
| 训练窗口 | 扩展窗口（从 `research_start` 到 τ）；对照跑一版滚动 12 个月 | 扩展窗口样本多、稳定；滚动窗口适应快 |
| 最短训练期 | 6 个月 | 第一个 τ 之前没有模型，打分为 NaN，相当于 alpha 的 warm-up |
| Purge | `horizon + delay` 根 bar | 跟关卡2 选择段末尾的 purge 同一口径 |

每一行的打分都来自**只用过去数据训练的模型**，拼起来是一条从第一个 τ 开始、全程样本外的打分序列。

### 7.2 MLAlpha.compute() 的行为

```text
compute(panel):
    features = build_features(panel, spec)           # 同一个特征函数
    for 清单里每个模型 j（按 valid_from 排序）:
        rows = panel.index 中落在 [valid_from_j, valid_until_j) 的行
        pred[rows] = model_j.predict(features[rows])  # 多种子取平均
    return pred（宽表，(T, N)）；清单覆盖不到的行为 NaN
latest(panel):  只用"valid_from <= 最后一根 bar 时间"的最新模型推断最后一行
```

- **point-in-time 测试**（写成单测）：对同一段数据，截断到 `t` 算出来的第 `t` 行，必须和用完整数据算出来的
  第 `t` 行完全相同。特征构建和模型选择两处都要过这个测试。
- `min_lookback` 取特征里最长的回看窗口；模型本身的 warm-up（第一个 τ 之前）由清单决定，输出 NaN。

### 7.3 和研究流水线的关系

| 流水线环节 | ML alpha 下怎么做 |
| --- | --- |
| 训练 | 研究线编排脚本里新增**步骤 0 · 滚动训练**（`run_training.py --track <研究线>`），在阶段一之前跑；模型已存在、配置没变时跳过 |
| 阶段一 | 照常。取选择段数据，`compute()` 只推断。选择段的打分已经是样本外的，IC 可以直接看 |
| 关卡1 / 关卡2 | 单模型研究线都透传，得到权重 +1 的单因子配方 |
| 关卡3 | 照常。取整个研究段，同一个清单推断，验证段的比较有效 |
| 和手工因子对比 | 另开一条研究线，同时收世坤因子和 ML alpha，关卡2 真跑：ML alpha 作为 `single:` 参照，直接和 G0 / L1 / L2 比 |
| holdout | 滚动训练继续按同样节奏覆盖 holdout，最后只跑一次 |

研究线示例（`research/alpha_research/custom_ml_lgbm_v1/track.json`）：

```json
{
  "id": "custom_ml_lgbm_v1",
  "alphas": { "modules": ["sherpa.alpha.custom.ml.models"], "family": "custom" },
  "preprocess": { "tradable_mask": true, "neutralize": true },
  "regime": { "dimensions": ["trend", "volatility", "dispersion", "liquidity"] },
  "report": { "matrix_top_k": 5, "min_abs_t": 3.0 },
  "stages": { "orthogonalization": { "mode": "passthrough" }, "synthesis": { "mode": "passthrough" } }
}
```

阶段一仍然按 regime 切片出条件 IC，但用途变了：不再用来决定方向，而是**诊断**模型在哪些市况下有效、哪些
市况下失效。

### 7.4 几个要注意的现有问题

- **universe 截止时间不同**：阶段一和关卡1 用 `Universe.as_of(validation_start)`，关卡2/3 用
  `Universe.as_of(research_end)`。多出来的只是验证段才上线的币，它们在选择段整列都是 NaN。截面运算只要正确
  跳过 NaN，结果就不受影响；实测所有已注册 alpha 和可流通性掩码都不受影响。唯一受影响的是趋势 regime 的
  市场广度（把 NaN 列当成"没涨"算进了分母），已在 `sherpa.metrics.regime.compute_trend_regime` 修复，并有
  单测覆盖。**ML 特征构建要守同一条规矩**：所有截面统计量只在当期有数据的 symbol 上算，不能让 NaN 列参与
  分母，否则特征会随面板的列数变化；§7.2 的 point-in-time 单测里加一条"多几列全 NaN 的币，结果不变"。
- **计算量**：特征里包含几十上百个现有 alpha，阶段一的多进程 worker 会把这些 alpha 重算一遍。第一版加一个
  特征缓存（按 `FeatureSpec` 版本 + 数据区间做 key，存 parquet），训练和推断都优先读缓存。
- **流动性掩码的来源**：训练样本的掩码和流水线外层掩码用同一个 `tradable_mask` 配置（研究线的
  `preprocess.tradable_mask`），避免"训练时看的币"和"评估时看的币"不一致。

### 7.5 实盘（暂缓）

实盘按同样的时间表在每个 τ 重训一次，追加进清单；`latest()` 自动用最新模型。因为回测里每一行本来就是由
"当时最新的模型"给出的，实盘和回测是同一套机制。按当前项目优先级（先做 alpha 研究和回测），实盘部分等研究
结论出来后再做，这里只保证设计上不需要返工。

## 8. 验收标准

1. **point-in-time 单测通过**（§7.2）。
2. **滚动样本外 IC**：选择段上逐折的 RankIC 均值为正，而且不是只靠一两折撑起来的。
3. **打赢基线**：关卡3 验证段、`all_taker` 成本下的净 Sharpe 高于最强单因子和世坤 G0 / L1。
4. **消融结论明确**：有 / 无状态变量、标签中性化 / 不中性化，各自对样本外 IC 和净 Sharpe 的影响。
5. **换手可接受**：关卡3 的换手衰减率低于红线（`MAX_TURNOVER_DECAY`）。

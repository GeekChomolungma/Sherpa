# 关卡3 结果阅读指南

`run_friction.py` 跑完后，按这份指南读研究线的 `results/friction/` 下的文件。目标是回答两个问题：

1. 有没有**稳健的**组合构建方式，在扣完成本之后还能赚钱？
2. 如果有，它能不能交给阶段二去跑 holdout？

最容易犯的错误是只看 `02_validation_base_cost.csv` 排第一的那一行。下面第 3 节的阅读顺序就是为了避免这一点。

---

## 1. 先弄清楚在比什么

### 1.1 一组回测做了什么

在每个调仓的 bar 上：

1. **可交易性掩码**：当期没有真实成交的币，分数设为 NaN，不参与排序；
2. **合成分数**：每个因子先算原始分数，剥离 Beta/Size 得到残差，再做截面排名，最后按 case 的配方合成一个分数；
3. **Top-K 建仓**：在剩下的币里，做多合成分数最高的 k 个、做空最低的 k 个，每个占 0.5/k 的资金，总敞口为 1（多空各 0.5）。有效币不足 2k 个时空仓；
4. **排名迟滞**（`_exitN`）：排进前 k 名才开仓，持有之后跌出前 N 名才平仓，空头按倒数排名对称处理。用来去掉边界附近来回进出的无效交易；
5. **调仓频率**（`everyN`）：每 N 根 bar 全仓调一次仓，中间不交易，持仓随价格漂移；
6. **执行时点**：信号在 t 收盘算出，晚 `execution_delay_bars` 根 bar 成交，赚的是跟 IC 标签同一段的收益。结果按**决策时点**记行。

### 1.2 网格的五个维度

| 维度 | 取值 | 来源 |
|---|---|---|
| case | 关卡2 的全部合成方案（G0 / L1 / L0 / 4 个 L2）+ 选择段最强的单因子 | 研究线的配方集交接文件 `handoff/synthesis.json`（关卡2 产出；透传时是 `直通·` 等权配方） |
| 映射 `weighting` | top10、top10_exit20/30/50，top20、top20_exit40/60/100 | `config.WEIGHTINGS` |
| 调仓频率 `rebalance_every` | 1 / 3 / 6 根 bar（4h 周期下是 4 小时 / 12 小时 / 1 天） | `config.REBALANCE_EVERY` |
| 成本 `cost_model` | `zero` / `all_maker` / `all_taker` / `stress` | `config.COST_MODELS`，费率来自 `research_config.json` 的 `costs` |
| 数据段 `segment` | 选择段（样本内参考）/ 验证段（比较以此为准） | `research_config.json` 的 `window` |

回测只跑 case × 映射 × 调仓频率这么多次。同一条收益序列扣不同的成本、再切成两段分别统计，就得到后两个维度，不需要重新回测。

四种成本：

| 成本 | 含义 | 怎么用 |
|---|---|---|
| `zero` | 不扣费，净 Sharpe 就是毛 Sharpe | 看信号本身兑现成收益的能力 |
| `all_maker` | 全部挂单，只扣挂单费，不计滑点 | **乐观上限**：没算挂单成交不了、逆向选择 |
| `all_taker` | 全部吃单，吃单费加常规滑点 | **保守口径，验收红线按它判定** |
| `stress` | 吃单加大滑点 | 看结论对滑点有多敏感 |

真实执行会落在 `all_maker` 和 `all_taker` 之间，具体取决于挂单能成交多少，目前还估计不出来。

## 2. 各个文件

### `00_case_consistency.csv`：先确认这个

关卡3 用关卡2 的配方重新算出分数，再按关卡2 同一口径算一遍验证段的 IC_IR，跟关卡2 报告的数字对照。**`consistent` 必须全部是 True**。有 False，说明配方重建或数据口径出了偏差（常见原因是关卡2 的结果过期了，或者 `research_config.json` 改过），后面的结果都不用看了。

### `case_grids/<case>.csv`：一个 case 的二维截面

每个 case 一个文件，验证段的净 Sharpe：

- 行：8 种映射；
- 列：`<成本>|every<N>`，共 4 种成本 × 3 种调仓频率 = 12 列。`zero|…` 那 3 列就是毛 Sharpe。

**找稳健区域主要看这里**（见 §3 第 2、3 步）。

### `02_validation_base_cost.csv`：全部组合的排名

验证段、`all_taker` 成本下，每个 (case, 映射, 调仓频率) 一行，按净 Sharpe 从高到低排序。

| 列 | 含义 | 怎么看 |
|---|---|---|
| `gross_sharpe` | 零成本 Sharpe | 信号本身能兑现多少。连它都低，组合构建再怎么调也没用 |
| `net_sharpe[all_maker]` | 全挂单的净 Sharpe | 乐观上限 |
| `net_sharpe` | 全吃单的净 Sharpe | 红线按它判定 |
| `net_sharpe[stress]` | 吃单加大滑点的净 Sharpe | 对滑点的敏感度 |
| `net_ann_return` / `net_max_drawdown` / `net_calmar` | 全吃单下的年化收益 / 最大回撤 / 收益回撤比 | |
| `net_ann_vol` | 全吃单下的年化波动 | |
| `turnover_per_bar` | 每根 bar 平均交易掉多少比例的资金 | 0.24 = 每 4 小时换手 24% |
| `turnover_per_year` | 年化换手倍数 | 500 = 一年把资金周转 500 遍 |
| `cost_drag_per_year` | 成本每年吃掉的收益 | |
| `turnover_decay` | 成本吃掉了毛利的多大比例 | 红线要求 < 40%。大于 1 表示扣完成本是亏的 |
| `breakeven_cost_bps` | 单边成本涨到多少 bps，净收益刚好归零 | **最直观的指标**：直接拿它跟实际费率比（当前挂单 2 bps，吃单 5+3 = 8 bps）。离实际费率越远越稳 |
| `flat_bar_fraction` | 空仓 bar 的占比 | 占比高时，Sharpe 是在很少的交易 bar 上算出来的 |
| `passes_red_lines` | 全吃单下净 Sharpe ≥ 2.5 且换手衰减 < 40% | |

### `01_friction_summary.csv`：完整长表

一行 = (case, 映射, 调仓频率, 成本, 数据段)，列跟上表相同。`case_grids` 和上面的排名都是从它 pivot 出来的。需要其他切法的时候用它，比如**选择段**的截面：

```python
import pandas as pd
d = pd.read_csv("results/01_friction_summary.csv")
sel = d[d.segment.str.startswith("selection") & (d.cost_model == "all_taker") & (d.case == "L0 并集等权")]
sel.pivot_table(index="weighting", columns="rebalance_every", values="net_sharpe")
```

### `03_validation_net_equity.csv`：净值曲线

验证段、全吃单成本下，净 Sharpe 前 30 名组合的净值曲线（宽表，一列一个组合）。用来看收益是不是集中在某一小段时间、回撤出现在什么时候。

## 3. 阅读顺序

以 2026-09 那一轮的 `L0 并集等权 | top10_exit50 | every3` 为例。它在 `02` 里排第一：全吃单净 Sharpe 1.00，全挂单 1.91，保本成本 14.6 bps。

### 第 1 步：看 `00`，确认一致性

8/8 全部为 True，可以继续。

### 第 2 步：看毛 Sharpe（`case_grids` 里的 `zero|…` 列）

信号本身能兑现多少。那一轮 L0 的格子在 0.8～2.2，全部 192 组的中位数只有 1.25，**连零成本都达不到红线 2.5**。也就是说，不管怎么调组合构建都过不了红线，瓶颈在信号本身。这一步就可以决定后面还值不值得花时间细看。

### 第 3 步：在截面上看它的邻居，不要只看排第一的那一格

打开 `case_grids/L0_并集等权.csv`，看 `all_taker|…` 那 3 列：

| | every1 | every3 | every6 |
|---|---|---|---|
| top10_exit30 | -0.67 | 0.09 | -0.26 |
| **top10_exit50** | 0.07 | **1.00** | 0.36 |
| top20_exit100 | 0.43 | 0.50 | 0.12 |

相邻的格子都在 0～0.5，只有它一格高到 1.0，说明它是**孤立的高点**。在 192 个组合里挑最高的一个，本来就会偏乐观，这种单格高点大概率是碰巧挑出来的。

**稳健的信号应该是一片区域都不错**。比如同一个文件的 `all_maker|…` 列，大部分带迟滞的组合都在 1.0～1.9，这片区域比 taker 下的那一格可信。

### 第 4 步：换一个 case，用同样的参数

同样是 top10_exit50 × every3，其他 case 在全吃单下是 -0.78～0.28，只有 L0 特别高。说明这个高分依赖 L0 的特定配方，不是这套组合构建方式普遍有效。

### 第 5 步：对照选择段

用 `01` 切出同一格的选择段：全吃单 0.49，全挂单 1.10，都明显低于验证段。**验证段远好于选择段时要警惕**：可能是验证段赶上了对这个因子特别有利的行情，而不是配方真的好。

### 第 6 步：对照成本敏感度

- 看 `breakeven_cost_bps` 离实际费率有多远：14.6 bps 对 8 bps 的吃单成本，余量不算大；
- 看 `stress` 下的表现：-0.06，滑点多几个 bps 就归零了。

### 第 7 步：看净值曲线在时间上是否均匀

用 `03` 把净值按季度拆开：验证段总收益 +62.7%，其中 **2025 Q4 一个季度就贡献了 +54.9%**，其余约 1.4 年里一共只赚了约 5%；最大回撤 -29.5%，从 2024-12 持续到 2025-04。收益高度集中在一段时间里，可复制性存疑。

### 结论

这个组合**不能进阶段二**。holdout 只能用一次，要留给一个在验证段上稳健、并且能达到红线的配方。

## 4. 判断标准速查

| 问题 | 在哪里看 | 什么情况算好 |
|---|---|---|
| 配方重建对不对 | `00` | `consistent` 全部为 True |
| 信号本身够不够强 | `case_grids` 的 `zero` 列 | 毛 Sharpe 明显高于 2.5，才有可能在扣费后过红线 |
| 结果稳不稳 | `case_grids` 的 `all_taker` 列 | 一片相邻的格子都不错，而不是单独一格 |
| 是不是只对这个 case 有效 | `01`，固定参数、按 case 对比 | 多个 case 用同样的参数都不差 |
| 是不是样本内碰巧 | `01` 选择段 vs 验证段 | 两段量级相近 |
| 对执行方式有多敏感 | `02` 的 maker / taker / stress 三列、`breakeven_cost_bps` | 保本成本明显高于吃单成本（当前 8 bps） |
| 收益是不是集中在一段时间 | `03` 按季度拆分 | 多数季度为正，没有单个季度贡献大部分收益 |
| 能不能进阶段二 | 以上全部 | 全吃单下验证段达到红线（净 Sharpe ≥ 2.5，换手衰减 < 40%），并且上面各项都通过 |

以后换了因子家族，用同一套网格重跑，跟这组数字比：

验证段，全部 192 组（8 case × 8 映射 × 3 调仓频率）：

| 指标 | 25% 分位 | 中位数 | 75% 分位 | 最好的一组 |
|---|---|---|---|---|
| 毛 Sharpe（`zero`） | 0.80 | 1.25 | 1.60 | 2.24 |
| 全挂单净 Sharpe | 0.39 | 0.69 | 1.04 | 1.91 |
| 全吃单净 Sharpe | -1.20 | -0.57 | -0.18 | 1.00（孤立高点，见 §3） |
| 保本成本（仅带迟滞的组合，bps） | 4.1 | 5.5 | 7.1 | 14.6 |

最好的 case 是 L0：全挂单下大部分带迟滞的组合在 1.0～1.9，全吃单下稳健区域约 0～0.5。

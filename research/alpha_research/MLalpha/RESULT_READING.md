# MLalpha 结果阅读指南（ML alpha 研究的主框架）

一个 ML alpha（或任何新的打分）到底行不行，按本文的顺序读结果、按本文的标准下结论。之后所有 ML alpha 研究（新特征、
新模型、NN……）都用这一套，跟基线 `LgbmV4` 比（2026-10-11 封版，§6）。

设计和代码见 [`sherpa/alpha/custom/ML_ALPHA_DESIGN.md`](../../../sherpa/alpha/custom/ML_ALPHA_DESIGN.md)、
[`research/ml_training/README.md`](../../ml_training/README.md)；关卡3 其它表（00 ~ 03、case_grids）的细节见
[`research/friction_test/RESULT_READING.md`](../../friction_test/RESULT_READING.md)。

## 0. 总原则：RankIC 是核心，收益表是确认

截面量化的本质是"用打分的排序预测未来收益的排序"（`QUANT_RESEARCH_TO_LIVE_LIFECYCLE.md` §5.0），所以**样本外 RankIC 是判断一个模型好坏的
核心指标**。关卡3 的 04 ~ 06 回答的是"这份排序能力扣掉成本、换成仓位之后还剩多少"，是对 RankIC 的**确认**，不是替代。

研究框架假设 RankIC 和收益直接挂钩：

- **RankIC 好、收益也好**：正常，结论成立；
- **RankIC 好、收益不好**：排序能力没有变成钱，要回到研究里找原因（成本、组合构建、标签口径），不能直接下结论"模型不行"；
- **RankIC 不好、收益好**：**不能拿收益替 RankIC 找补**。这种收益来自研究框架之外的东西（风格、尾部几个币、某几个季度的运气），按噪音处理；
- 两者长期对不上（比如 §5.4 的挂钩检查相关很低）：说明我们衡量的 RankIC 跟交易实际赚的东西之间隔着一层没研究清楚的东西，这是研究框架本身要补的，
  不是在两个指标之间挑一个对自己有利的看。

历史上的例子：LgbmV1 的 RankIC 0.056 却不赚钱（2026-10-01）。原因是当时的 IC 是对"排名标签"算的，奖励的是"中位数效应"，跟 Top-K 等权
赚的平均收益不是一回事——于是改了标签（原始收益），V2 以后两者才对得上。这是"背离 → 回到研究里修"的正确处理方式。

## 1. 先分清几个词

| 词 | 指什么 | 例子 |
| --- | --- | --- |
| **模型 / alpha** | 一个注册的打分来源 | `custom.ml_lgbm_v4` |
| **种子集成** | 每个重训时点训练多个随机种子的模型，推断时**取平均**成一份打分。对后面所有评估来说，一个 alpha 就是**一份**打分，种子不是单独的样本 | V4：18 个种子 |
| **重训时点 / fold** | 每 20 天（120 根 4h bar）训练一次模型，每个模型只负责下一个 20 天的打分。研究段一共 50 个 | `valid_from = 2024-07-09` |
| **run** | 一次正式研究线运行，产出在 `runs/<run_id>/`，`run_id` = 参评模型的 `model_name` | `runs/lgbm_v4/` |
| **case** | 关卡3 里的一行配方 = 一个打分来源。单模型研究线透传后就是 `single:<alpha>` | `single:custom.ml_lgbm_v4` |
| **组合** | 把**同一份**打分变成仓位的一种具体方式 = 映射 × 调仓频率。13 种映射 × 3 种调仓频率 = **39 个组合** | `q10_exit30`，每 3 根调仓 |
| **映射** | 每边选几个币、迟滞多宽。`top10_exit50` = 绝对名次（前 10 开仓、跌出前 50 平仓）；`q10_exit30` = 相对分位（前 10% 开仓、跌出前 30% 平仓） | |
| **段** | 选择段 `2023-01-01 ~ 2024-06-30`（ML 模型从 2023-06-30 起才有打分）；验证段 `2024-06-30 ~ 2026-03-15`；holdout `2026-03-15 ~ 2026-09-15` 不碰。为什么要分段见 §8 | `research_config.json` |
| **成本** | `zero`（毛收益）/ `all_maker`（全挂单 2 bps，乐观）/ `all_taker`（全吃单 5 + 3 = 8 bps，**主口径**）/ `stress`（吃单 + 大滑点） | |

**一个组合在一个段上只有一个 Sharpe**（用这一段所有 bar 的逐 bar 净收益算）。04 里的"中位数"，是同一个 case 的 39 个组合的 Sharpe 取中位数——
不是跨种子、也不是跨时间。

## 2. 三种 IC，口径各不相同

同一个模型会在三个地方报 IC，标签、数据段、掩码都不一样，**只有同口径的数才能放在一起比**：

| 出处 | 标签 | 数据段 | 掩码 | 粒度 | 用途 |
| --- | --- | --- | --- | --- | --- |
| `ml_training/<model>_folds.csv` / `_oos_summary.csv` | **训练标签**：V2 起是 6 根未来收益（`label_horizon_bars`） | 全研究段，按 fold | 训练用的损失掩码（= 研究线评估掩码） | **每个 fold 一个数（20 天）**，`oos_summary` 按段汇总 | **主指标**：时间序列、模型横比、趋势（§5） |
| `report/`（阶段一）、`regime_alpha_profile_*.csv` | 研究配置的标签：1 根（`research_config.json` 的 `label`） | **只有选择段** | 研究线评估掩码 | 整段一个数，按 regime state 切 | regime 诊断：在哪些市况下有效 |
| `friction/00_case_consistency.csv` 的 `recomputed_validation_ic_ir` | 1 根 | **只有验证段** | 同上 | 整段一个数 | 跟阶段一同口径的验证段 IC_IR |

注意：

- folds 的 IC 是对**各模型自己的训练标签**算的，训练标签持有期不同的模型（V1 持有 1 根，V2 起 6 根）不能直接比，这时用阶段一 + `00` 的 1 根口径；
- 1 根标签的 IC 两段拼起来才完整：选择段看阶段一的 `unconditional / ALL`，验证段看 `00`；
- 6 根标签相邻期重叠，每个 fold 内的 `rank_ic_ir` 偏高（自相关），**跨 fold 比较用 `rank_ic_mean`**。

## 3. 一次运行的产出（`runs/<run_id>/`）

```text
research/alpha_research/MLalpha/
  models/<model_name>/manifest.json            每个重训时点的模型、早停轮数、内部验证 IC_IR（模型文件本身不进 git）
  runs/<run_id>/                               一次正式运行的全部产出（MLalpha 研究线 neutralize=false，所以都带 _without_neutralization）
    regime_alpha_profile_without_neutralization.csv     阶段一长表
    handoff_without_neutralization/                     各阶段交接文件（report / orthogonalization / synthesis.json）
    results_without_neutralization/
      track_run.log                                     整条研究线的运行日志
      ml_training/                                      步骤 0：训练自检
      report/                                           步骤 1–2：阶段一体检 + 汇总报告
      friction/                                         步骤 5：关卡3 扣费回测
```

### 3.1 根目录：阶段一长表和交接文件

| 文件 | 内容 |
| --- | --- |
| `regime_alpha_profile_without_neutralization.csv` | 阶段一长表：每个 (alpha, 维度, state) 一行，列 `samples, ic_mean, ic_std, ic_ir, win_rate, t_stat, p_value`；`dimension = unconditional, state = ALL` 是全选择段基线。1 根标签、只有选择段 |
| `handoff_without_neutralization/report.json` | 候选集：每个 state 通过显著性门槛（`min_abs_t`，MLalpha 是 2.0）的因子。单模型时只用来确认"模型在各 state 都显著" |
| `…/orthogonalization.json` | 关卡1 透传，内容同上 |
| `…/synthesis.json` | 关卡2 透传出的配方：`single:<alpha>`，权重 +1 |

### 3.2 `ml_training/`：训练自检，也是 RankIC 时间序列的主来源

| 文件 | 一行是什么 | 列 |
| --- | --- | --- |
| `<model>_folds.csv` | **一个重训时点**（50 行） | `valid_from / valid_until`（这个模型负责的 20 天）、`n_train_rows`（扩展窗口，越往后越多）、`best_iterations`（每个种子的早停轮数，竖线分隔；树模型 = 棵数，LSTM = epoch 数）、`inner_valid_ic_ir`（训练窗口里内部验证段的 IC_IR，只用于早停）、`periods`（负责期内的 bar 数）、**`rank_ic_mean` / `rank_ic_ir` / `rank_ic_win_rate`（负责期内逐 bar 截面 RankIC 的均值 / IR / 为正比例，纯样本外）** |
| `<model>_oos_summary.csv` | 一个段 | 把所有 fold 的逐 bar RankIC 拼起来，按选择段 / 验证段 / 全部汇总 |
| `<model>_ic_by_bar.csv` | 一根 bar | **逐期样本外 RankIC**（`rank_ic`），附这一期参与的币数 `n_symbols`、负责它的重训时点 `fold_valid_from`、所属段 `segment`。上面两张表都是它的汇总；画排序能力的时间序列（`research/viz/`）用它。2026-10-27 起才有 |
| `<model>_train_config.json` | 一个模型 | **这次 run 的模型是怎么训练的**：`train_window`（扩展 / 滑动多少天）、后端、标签、种子等全部训练参数（跟模型清单同一份），以及特征 / 配置指纹 |

`<model>_folds.csv` 还有三列训练窗口：`train_from` / `train_until` / `train_days`。扩展窗口的 `train_from` 一直是研究起点、`train_days` 越来越大；
滑动窗口的 `train_days` 涨到窗口长度后固定、`train_from` 每 20 天往前挪（历史不满窗口长度之前两者一样）。2026-10-26 以前的 run 没有这三列和
`train_config.json`，窗口看模型清单 `models/<model_name>/manifest.json` 的 `config.train_window_bars`（`null` = 扩展）或 §6 的说明。

怎么读：

- `rank_ic_mean` 按时间排开就是这个模型**排序能力的时间序列**（每 20 天一个点），是 §5 横比的基础；
- `best_iterations` 大量是 1（第一棵树 / 第一个 epoch 就早停）说明后面学不到东西；`inner_valid_ic_ir` 忽高忽低是正常的（只有 20 天，噪声大）；
- `oos_summary` 两段量级应该相近；选择段明显高于验证段，说明要么市场变了，要么研究决策在选择段上有偏（§8）。

### 3.3 `report/`：阶段一体检（只有选择段，1 根标签）

单模型研究线里只用来做 **regime 诊断**：模型在哪些市况下排序能力强、哪些弱。

| 文件 | 内容 |
| --- | --- |
| `IMPORTANT_FINDINGS.md` | 自动生成的摘要：数据健康、分类计数、每个 state 的 Top 因子（进 git） |
| `00_dataset_summary.csv` / `thresholds.json` / `validation.json` | 数据集规模、分类用的阈值（\|IC_IR\| 分位数等）、长表校验（缺行、重复） |
| `01_factor_overview.csv` | 每个 alpha 一行：分类（Stable / Conditional / Regime-Reversal …）、全历史基线 IC、最好的 state、最敏感的维度 |
| `02_dimension_diagnostics.csv` | 每个 alpha × 维度一行：各 state 的 IC_IR 差距（`ir_spread`）、有没有符号翻转、最好 / 最弱的 state |
| `03_regime_leaderboard.csv`、`leaderboards/<维度>_<state>_top.csv` | 每个 state 内的排行（单模型时只有一行） |
| `04_regime_matrix.csv` / `05_global_matrix.csv` | 每个 state 的 Top-K（显著性门槛 + \|IC_IR\| 排序），给关卡1 的候选集就从这里来 |
| `dimensions/<维度>_report.csv` | 每个维度一张宽表：各 state 的 `samples / ic_mean / ic_std / ic_ir / win_rate` 并排 |

读法：看 `regime_alpha_profile` 或 `dimensions/*_report.csv` 里各 state 的 `ic_ir` 和 `t_stat`——有没有 state 不显著、有没有符号翻转、最弱的是哪一档。
跟另一个模型横比时，看"同一个 state 下谁更强"，以及弱点是不是同一档（弱点相同 = 合成也补不上）。

### 3.4 `friction/`：关卡3 扣费回测（确认排序能力变成了钱）

| 文件 | 一行是什么 | 用途 |
| --- | --- | --- |

| `01_friction_summary.csv` | case × 映射 × 调仓频率 × 成本 × 段 | 完整长表：`gross/net_sharpe`、`net_ann_return / vol`、`net_max_drawdown`、`net_calmar`、`turnover_per_bar / per_year`、`cost_drag_per_year`、`turnover_decay`、`breakeven_cost_bps`、`flat_bar_fraction`。其它表都从它来 |

## 4. 单个模型的阅读顺序

### 第 1 步：排序能力（RankIC）——**主判据**

1. `ml_training/<model>_oos_summary.csv`：两段样本外 RankIC 都为正、量级相近；
2. `ml_training/<model>_folds.csv` 的 `rank_ic_mean` 按时间排开（§5）：大多数 fold 为正、没有持续下降的趋势、不是靠前面几个 fold 撑起来的；
3. 阶段一（选择段）+ `00`（验证段）的 1 根口径 IC_IR：两段方向、量级一致；
4. 阶段一 regime 切片：各 state 都显著，记下最弱的那一档。

### 第 2 步：`04_robustness.csv` —— 排序能力换成仓位扣费后还剩多少

| 列 | 含义 |
| --- | --- |
| `n_combos` | 计入的组合数 |
| `selection_median` / `validation_median` | 39 个组合在该段的扣费净 Sharpe 中位数 |
| `selection_positive_frac` / `validation_positive_frac` | 该段净 Sharpe > 0 的**组合**占比 |
| `both_positive_frac` | **两段都 > 0 的组合占比** |

- 先看 `all_taker` 行（主口径）；再看 `zero`（毛收益，信号本身）和 `all_maker` / `stress`（成本敏感度）；
- **跟第 1 步对照**：哪一段 RankIC 高，哪一段收益就应该高。对不上就按 §0 处理；
- 不要只看网格里最高的那一格（多重检验）。

### 第 3 步：`06_quarterly.csv` —— 时间上稳不稳，跟 RankIC 的时间序列对得上吗

- 看稳健区域的组合 `positive_quarter_frac`，再看是哪几个季度亏、亏得是否集中；
- 把季度收益跟同季度的 fold RankIC 均值放在一起看（§5.4 的挂钩检查）：IC 低的季度收益也低，才说明收益是排序能力带来的。

### 第 4 步：`05_style_attribution.csv` —— 赚的是什么钱（**诊断，不做门槛**）

吃单净收益对 6 个风格收益做时间序列回归 `r_t = α + Σ β_j · f_j,t + ε_t`：

| 风格 | 做多 / 做空 |
| --- | --- |
| `btc` | BTC 自己 |
| `market` | 掩码内全部币等权（山寨币整体） |
| `low_vol` | 近 42 根波动最低 20% / 最高 20% |
| `small_size` | 近 42 根成交额最小 20% / 最大 20% |
| `reversal` | 近 6 根跌最多 20% / 涨最多 20% |
| `momentum` | 近 120 根涨最多 20% / 跌最多 20% |

`beta[*]` 是风格暴露，`r2` 是风格能解释的方差比例，`alpha_sharpe` 是剥离风格后的 Sharpe（= α / std(ε) × √每年 bar 数），`alpha_t` 是 α 的普通 OLS
t 值（偏乐观）。2026-10-24 起不作门槛：β 是同一段上样本内拟合的，不是能交易的对冲。用来解释"收益来源变了没有"，比如两个模型 RankIC 差不多、
收益差很多时，看是不是风格暴露不同。

### 第 5 步：`02_validation_base_cost.csv` / `case_grids/`

前几步确认"这个打分值得用"之后，才来这里挑具体的映射和调仓频率：选**一片都不错的区域的中间**，不要选孤立的最高点。

## 5. 模型横比：看时间序列、近期和趋势，不只看一个中位数

整段的中位数会把"前面很强、后面变弱"和"一直平稳"压成同一个数。横比两个模型时，**以 RankIC 的时间序列为主**，按下面的顺序做。

### 5.1 前提：可比的条件

- 同一套数据、同一个研究窗口、同一个关卡3 网格（各自纯模式跑完整研究线，`runs/<a>/` vs `runs/<b>/`）；
- 同一个 IC 口径（§2）：训练标签持有期相同才能比 folds 的 IC，否则用 1 根口径；
- 两个模型的重训时间表相同（都从研究起点按每 20 天排，`valid_from` 一一对应）；
- **先确认两边的训练窗口**（`train_config.json` 的 `train_window`）：窗口不同的两个模型比的是"架构 + 窗口"两件事，结论要说清楚；比较不同窗口时，
  只有历史超过窗口长度之后的 fold 是不同的（365 天窗口要到 2024 年初才开始滑动）。

### 5.2 配对比较：逐 fold 相减

两个模型的 `<model>_folds.csv` 按 `valid_from` 对齐，算 `d_k = IC_A,k − IC_B,k`（k = 第 k 个 fold）。**同一个 20 天、同一批币**，大盘涨跌、
币池大小这些共同因素都抵消掉了，比分别算两个均值再相减灵敏得多。对每个时间窗口报三个数：

| 数 | 含义 |
| --- | --- |
| `mean(d)` | 平均领先多少 |
| `t = mean(d) / std(d) × √n` | 领先是否显著（\|t\| ≥ 2 才算） |
| `d > 0` 的 fold 数 / n | 胜出的频率 |

时间窗口至少看四个：**选择段、验证段、最近约 1 年（18 个 fold）、最近约 8 个月（12 个 fold）**。做决定只看选择段；验证段确认；最近的窗口回答
"现在谁更强"。

### 5.3 趋势：排序能力在变强、平稳还是衰减

- **线性趋势**：对 `rank_ic_mean` 关于 fold 序号做回归，斜率 × 18 ≈ 每年变化多少；
- **前后对比**：前 18 个 fold vs 最近 18 个 fold 的均值；
- **滚动均值**：3 个 fold（约 2 个月）滚动平均，看最近的位置。

衰减的模型即使整段中位数更高，也不能直接替换平稳的模型。衰减要先查原因（币池变化、训练窗口、某类特征失效），而不是等它自己恢复。

### 5.4 挂钩检查：收益是不是跟着 RankIC 走

把每个季度的 fold `rank_ic_mean` 均值，跟 `06_quarterly.csv` 同季度的吃单收益（39 个组合的中位数）放在一起，算相关。框架假设两者挂钩：

- 相关明显为正：收益来自排序能力，04 ~ 06 的结论可以作为 RankIC 结论的确认；
- 相关很低：收益里有大量排序能力以外的东西，**这时 04 ~ 06 的领先不能作为模型更好的证据**，结论以 RankIC 为准，同时把"为什么挂钩弱"记成待研究的问题。

### 5.5 关卡3 的确认

最后才看 04 / 06 / 02 的整段数字，确认 RankIC 的结论变成了钱。04 两段中位数的领先要大于随机波动（±0.15–0.2），结论至少两组不重叠的种子都成立。

### 5.6 实例：LgbmV4 vs LstmV5（扩展窗口版，2026-10-26，`runs/lstm_v5__expanding/`）

| | LstmV5 − V4（6 根 RankIC，逐 fold 配对） |
| --- | --- |
| 选择段（19 个 fold） | +0.022，t +3.75，LSTM 胜 16 / 19 |
| 验证段（31 个 fold） | **−0.013，t −2.98，LSTM 胜 8 / 31** |
| 最近约 1 年（18 个 fold） | **−0.020，t −4.61，LSTM 胜 2 / 18** |
| 最近约 8 个月（12 个 fold） | −0.016，t −3.98，LSTM 胜 1 / 12 |

| 趋势 | V4 | LstmV5 |
| --- | --- | --- |
| 线性趋势（每年） | +0.001（平稳） | **−0.021（衰减）** |
| 前 18 个 fold → 最近 18 个 fold | 0.065 → 0.072 | 0.087 → 0.052 |
| 最近 3 个 fold 滚动均值 | 0.046 | 0.027 |
| 1 根口径 IC_IR 选择段（阶段一）/ 验证段（`00`） | 0.225 / 0.326 | 0.315 / 0.286 |
| 挂钩检查：季度 RankIC vs 季度收益的相关（11 个季度） | +0.32 | +0.28 |

结论：LstmV5 **只在选择段更强**，验证段和最近一年都显著弱于 V4，而且在衰减；04 / 06 上验证段的收益领先（0.73 vs 0.49）没有排序能力支撑，
挂钩检查的相关也很低，按 §0 不能作为它更好的证据。**V4 仍是基线**。两个模型的挂钩相关都只有 0.3 左右，说明"全截面 6 根 RankIC"跟 Top-K
实际赚的钱之间还隔着一层没研究清楚的东西，这是框架要补的（§7）。细节见 [`comparisons/v4_lstm_v5/README.md`](comparisons/v4_lstm_v5/README.md)。

## 8. 为什么要分选择段和验证段（训练明明是全程滚动的）

**训练本来就没有分段。**每个重训时点 τ 都用"研究起点到 τ 之前"的全部数据训练（扩展窗口），选择段和验证段的模型是同一个滚动过程连续产出的，
两段的打分都是样本外的。分段只用在**评估和做决定**上，不影响训练。

分段要防的不是"模型参数过拟合"（滚动训练已经防住了），而是**研究者的决定过拟合**：

- 用哪组特征、哪种模型、哪个超参数、选 seq_len 6 还是 30——这些决定都是**看着结果做的**。每看一次、选一次，被看过的那段数据对"这些决定"来说
  就不再是样本外了。V1 → V4 → LstmV5 一路试过几十个配置，如果都在全段上挑，挑出来的那个天然偏乐观（多重检验），而且没有任何一段数据能告诉你
  偏了多少；
- 所以规定：**做决定只看选择段，验证段只用来确认**。选择段的数字是"挑选过的"，验证段的数字是"没被挑选碰过的"，两者的落差本身就是信息——LstmV5
  选择段 RankIC 显著高于 V4、验证段反而显著低于 V4，这就是"选择段上的优势没有泛化"的证据；合成一段就看不到了；
- 非 ML 研究线（世坤 101）的阶段一挑因子、关卡2 估权重都只在选择段上做，关卡3 在验证段上比较方案，ML 研究线跟它们共用同一套流水线和切分；
- holdout 是第三道：所有决定（包括"看了验证段之后又做的决定"）定下来之后只跑一次。

验证段也会被"用旧"：每次看了验证段再回去改配置，验证段就慢慢变成了另一个选择段。所以验证段的结论只用来"确认 / 否决"，不用来"再挑一个更好的"；
最终的判断留给 holdout。

## 9. 新想法的研究流程

```text
1. 筛选（快）：research/ml_training/run_experiments.py 里加 case，跟基线的 model_case("m_v4", ..., "LgbmV4") 比
   - 一次只改一件事（一组特征 / 一种损失 / 一种模型），多种子集成；比较要同批、同种子组、同窗口
   - 探索的执行层（39 个组合、成本、04/05/06 口径）跟关卡3 完全相同（CASES.md §0.2、§3），summary.csv 的列直接对应 04/05/06
   - 挑配置只看选择段，验证段只用来确认；先看 RankIC，再看 04 的中位数和两段都为正，不看最高格
2. 定型：把结论写成 models/ 里一个新的 MLAlpha 子类（spec + training_overrides），再用 model_case 绑定它在探索里跑一次
3. 确认（正式）：`run_track.sh --alphas <新模型>` 跑完整研究线（产出在 `runs/<model_name>/`）；结果应跟第 2 步的探索一致
   （树模型逐位相同；LSTM 打分截面相关 ≥ 0.999）。按本文 §4 读，按 §5 跟 V4 横比
4. 全部定下来之后，holdout 只跑一次
```

## 10. 常见陷阱

| 陷阱 | 说明 |
| --- | --- |
| 拿收益替 RankIC 找补 | RankIC 不好、收益好，收益来自框架以外的东西，按噪音处理（§0） |
| 只比整段中位数 | 会把"前强后弱"和"一直平稳"压成同一个数。做 §5 的配对比较和趋势 |
| 不同口径的 IC 放在一起比 | 1 根 / 6 根标签、选择段 / 验证段、fold 内 IR / 跨 fold 均值各不相同（§2） |
| 用验证段挑配置 | 验证段只确认；看了验证段再改，验证段就变成了选择段（§8） |
| 看网格最高的那一格 | 多重检验：39 个组合 × 多个 case，最高格天然偏乐观。看中位数和 `both_positive_frac` |
| 单个种子的结果 | 单个模型随机性很大（树模型两组种子的打分截面相关只有 0.43–0.68），没做集成的结果不可信 |
| 宽 Top-K 在小币池里空仓 / 不平仓 | 早期每期只有 50–90 个币：top30 需要 60 个币才建仓、exit80 几乎从不触发平仓。优先看相对分位映射（`q*`）；04 已剔除空仓 > 20% 的组合 |
| `03` 的净值曲线当成整体表现 | 它只有验证段、只有挑过的前 30 名组合 |
| 选择段偏乐观 | 研究决策都在选择段上做；B 组世坤因子名单也是在世坤研究线选择段上挑出来的 |
| 挂单假设 | `all_maker` 假设全部挂单成交、无逆向选择，是乐观上限；资金费率还没建模 |

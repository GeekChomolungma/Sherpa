# overlays/：打分之上的叠加层（"看不清就不参与"）

> 2026-10-25 第九批探索的分析脚本。结论见上一级的 [`FINDINGS_BACKENDS.md`](../FINDINGS_BACKENDS.md) §3–§4。
> 本目录是**探索用的研究代码**（路径写死、没有单测、产出不进仓库），不是正式流水线的一部分；验证有效的做法怎么进正式流水线见 §3、§4。

## 1. 叠加层是什么

现有流水线里，模型只管打分；打分变成仓位的方式是固定的——每个调仓时点都满仓做多 Top-K、做空 Last-K，**没有"这一期少押点"或
"这个币这期不碰"的选项**。叠加层就插在这两步之间，不改模型，也不改组合构建：

```text
特征 → 模型 → 截面打分 ──→ 【叠加层】 ──→ 打分变成仓位（Top-K + 迟滞） → 调仓 / 扣费
           第一层，不动                     第二层（关卡3 那套），不动
```

叠加层有三种形式：

| 类型 | 决定什么 | 作用在哪 | 例子 |
| --- | --- | --- | --- |
| **A. 打分合成** | 信谁的打分、怎么合成 | 打分 (T, N) | 树模型 + LSTM 两张打分各自截面排名后等权平均 |
| **B. 币层面过滤** | 哪些币这一期不进多头也不进空头（敞口不变，名额由别的币补上），或只是不进某一边 | 打分 (T, N)：把这些格子置 NaN / 抬到中位数 | 两个模型方向相反的币不碰；不做空截面波动最高的币 |
| **C. 时间层面敞口** | 这一期总共押多少：目标权重 × g_t，g_t ∈ [0, 1]，0 = 空仓 | 目标权重 (T, N)，只在调仓行 | 大盘近 7～20 天单边程度高时线性减仓 |
| （D. 对冲） | 在原组合之外加一笔对冲仓位 | 目标权重 (T, N) | 按组合净 beta 在 BTC 上反向对冲 |

几条共同的规矩（所有脚本都守）：只用 t 时刻已知的数据；门槛只在**选择段**上定（取信号在选择段上的分位数），验证段只用来确认；
回测口径跟关卡3 相同（39 个组合、吃单 8 bps、shift = 2、选择段 / 验证段按决策时点切）。

**"不参与"≠"不调仓"**：C 类的 g_t = 0 是把仓位降到 0（PnL 曲线变平，平仓和重新建仓的换手照常扣费），不是"拿着上一期的旧仓位不动"——
后者省换手，但旧仓位照样承担风险，做不到"不参与"。本批只测了前者。

## 2. 每个脚本对应哪一类

| 脚本 | 类型 | 回答的问题 | 本批结论 |
| --- | --- | --- | --- |
| `probe_folds.py` | —（模型层的快速探测，不是叠加层） | 正式跑之前，各后端 / 超参数在选择段上的截面能力（RankIC、首尾价差） | 定下 XGBoost 默认参数、LSTM 6 / 30 两个版本 |
| `dd_anatomy.py` | —（诊断） | 回撤是排序能力坏了，还是组合结构在亏？逐月拆净收益、多 / 空腿、IC、首尾价差、风格收益 | V4 亏在空头腿被轧，月均 IC 仍为正 |
| `regime_analysis.py` | —（诊断，给 C 类找信号） | 回撤在什么行情里；十来个候选信号按选择段分位切桶，看下一根的策略收益 | V4 怕大盘单边；合成打分上找不到两段一致的信号 |
| `gate_eval.py` + `gate_summary.py` | **C** | 大盘不清晰时减仓：37 种开关（信号 × 窗口 × 硬 / 软 × 门槛）× 39 个组合 | 只对偏低波动的 V4 有效，不通用 |
| `hedge_eval.py` | **D**（可叠加 C） | 按滚动 beta 用 BTC 对冲组合净 beta | 更差，排除 |
| `tail_eval.py` | **B**（可叠加 C） | 不做空（或两边都不碰）截面波动最高的那一档 | 只对 V4 有效，不通用 |
| `agree_eval.py` | **A + B**（可叠加 C） | 两个模型等权合成；方向相反的币不碰；整体分歧大时减仓（C） | **不同架构**的模型之间"等权合成 + 方向相反不碰"有效，两组种子都成立；整体分歧减仓有害 |

依赖：`hedge_eval` / `tail_eval` / `agree_eval` 从同目录的 `gate_eval` 引用开关信号（`gate_signals` / `make_gate`），`agree_eval` 还复用
`tail_eval` 的回测函数，所以要放在一起。输入都是探索产出的 `experiments/<case>/scores.pkl`（`agree_eval` 另外把合成后的打分存成
`blend.pkl` / `agree_coin.pkl`，可以再喂给 `gate_eval` / `regime_analysis` / `dd_anatomy`）。用法写在每个脚本开头。

## 3. 以后怎么进研究流水线（阶段一 + 关卡1～3）

原则：叠加层是"配方"的一部分，跟因子、权重一起在关卡2 冻结，关卡3 照配方复现、再换不同交易方式检验——跟现在的配方集是同一套机制，
不新开旁路。阶段之间仍然只靠 handoff 交接。

| 环节 | 要改什么 | 说明 |
| --- | --- | --- |
| 阶段一 | 不改 | 叠加层不是因子。参与合成的每个模型照常作为单个 alpha 过阶段一（拿方向符号、诊断） |
| 关卡1 | 不改逻辑；可以顺带报告候选模型之间的截面相关 | B 类"方向相反不碰"只在**不同架构**之间有效（相关约 0.5 有效，0.8 以上无效），关卡1 本来就算相关矩阵，正好用来挑"值得互相校验"的模型 |
| 关卡2 | **配方格式加可选的 `overlay` 一节**（`research/_shared/handoff.py`，升 `SCHEMA_VERSION`）；透传模式加一个开关产出合成配方 | A 类就是现有的 static 配方（等权，按排名合成，已支持）。B / C 类需要新字段，例如：`"overlay": {"coin_filter": {"kind": "sign_agreement", "alphas": [a, b]}, "exposure": {"signal": "abs_btc_42", "kind": "soft", "lo": <选择段 60% 分位>, "hi": <选择段 95% 分位>}}`——**门槛是关卡2 在选择段上估好的数字**，写进配方冻结，下游不再估 |
| 关卡3 | `case_scores` 之后按配方做 B 类过滤；`target_path` 之后按配方乘 C 类敞口；02 / 04 加 `in_market`、`avg_exposure` 两列 | 应用逻辑放在 `sherpa`（见 §4 的共享函数），关卡3 和探索的 `evaluation.py` 都调它，两边口径不会分叉；39 个组合、成本、04/05/06 不变 |
| 探索脚本 | `run_experiments.py` 加一种 `source`（比如 `agree:<case_a>+<case_b>`） | 让合成 / 过滤后的结果也出 `summary.csv` 的同口径一行，能直接跟 V4 比 |

## 4. 以后怎么进回测 / 实盘流水线（阶段二及以后）

原则：叠加层**会改变决策结果**，必须回测和实盘走同一份代码，不能写进某个 sink（`docs/SHERPA_DESIGN.md` §8.3 决策1）。现在的结构里，
`Runner` 主循环对回测和实盘是同一个；策略的 `BaseStrategy.on_bar` 也是两种驱动共用的。所以叠加层放在 `on_bar` 里，"打分 → 目标仓位"之间，
实现做成 `sherpa` 里的纯函数——跟 `sherpa.portfolio.weighting` 的设计一样，同一个函数在研究回测和 `on_bar` 里调用。

```text
Runner.run（回测 / 实盘同一个主循环，不改）
  └─ AlphaEngine.compute(event.panel)          各模型当前这根 bar 的打分
  └─ strategy.on_bar(event, features)          ← 叠加层在这里
       ① 每个模型打分截面排名                    同关卡3
       ② A：按冻结配方合成                        sherpa.backtest.score_backtest.weighted_composite（已有）
       ③ B：币层面过滤（方向相反的置 NaN）          新的纯函数，比如 sherpa.portfolio.overlay.sign_agreement_filter
       ④ 打分 → 目标权重（Top-K + 迟滞）           sherpa.portfolio.buffer.top_k_hysteresis（已有；上一期状态存在策略对象里）
       ⑤ C：乘敞口系数 g_t（只在调仓 bar）          新的纯函数，比如 sherpa.portfolio.overlay.exposure_scale
       → TargetPosition
  └─ sink.submit(...)                           只做派发格式化，不碰决策（不改）
```

几个落地时要注意的地方：

1. **"不参与"要显式发 0 仓位**：`Runner._to_intents` 在 `TargetPosition` 为空时**不发任何信号**，下游会继续拿着旧仓位。C 类 g_t = 0 时
   必须返回"所有持仓 symbol 的目标仓位都是 0"，而不是返回空——否则实盘的行为就成了"不调仓"，跟回测（降到 0）对不上。
2. **回看长度**：C 类信号要大盘的历史（比如 BTC 近 42 / 120 根 4h bar），B 类要两个模型都能打分（LSTM 要 `seq_len − 1` 根额外历史）。
   叠加层要像 alpha 一样声明 `min_lookback`，`HistoricalPanelSource` / `LivePanelSource` 给的窗口不能短于各模型和叠加层里最长的那个。
3. **门槛不在线重估**：C 类的 lo / hi 是关卡2 冻结进配方的数字，回测 / 实盘照用；要重估就回到关卡2 重新冻结、整体重新验证
   （lifecycle §5.0：阶段二是验证，不是搜索）。
4. **迟滞状态**：Top-K 迟滞依赖上一期的持仓方向，B 类过滤后某个币被剔除就会被平仓；这个状态由策略对象自己维护，跟现在的写法一致。
5. **一致性核对**（阶段三）：离线回测和纸面交易的逐笔对比要包含叠加层的输出（被过滤掉的币、每期的 g_t），不只是最终仓位。

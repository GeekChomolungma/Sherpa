# MLalpha 探索实验：4h 截面上的盈利点（2026-10-05）

> 注意：本文的实验都是在研究起点 **2022-01-01** 下跑的。之后研究起点改到了 2023-01-01（`research_config.json`），
> 结论被做成了正式基线 `LgbmV2`（`sherpa/alpha/custom/ml/models.py`），新起点下的正式结果在研究线
> `results_without_neutralization/` 里。本文的数字留作历史记录。

工具：`research/ml_training/run_experiments.py`（case 定义 + 滚动训练 + 样本外打分）、`research/ml_training/evaluation.py`（关卡3
同口径的扣费回测 + 诊断）。每个 case 的结果在本目录 `<case>/`，全部 case 的汇总在 `summary.csv`（CSV、模型、打分缓存都不进 git，
重跑 `python run_experiments.py --summary-only` 可以重新生成汇总）。

---

## 1. 结论摘要

1. **毛 alpha 是存在的，但不在第一版用的那套设定里。** 要同时满足：**原始收益标签**（不是截面排名）+ **标签持有 1 天**（6 根 bar）
   + **世坤因子（B 组）在特征里** + **宽迟滞的低换手持仓**。这样的模型零成本毛 Sharpe 中位数：选择段 0.4–0.6，验证段 1.5–2.4。
2. **扣掉吃单成本（8 bps）后，只在验证段（2024-06-30 ~ 2026-03-15）稳定为正。** 最好的一族 `h6_raw_exp_ens9`（扩展窗口、9 个种子
   集成）验证段扣费净 Sharpe 中位数 1.26，多数组合在 0.8–2.1。但**选择段（2022-07 ~ 2024-06）几乎所有 case 的中位数都是负的**，
   只有零星组合为正。所以目前只能说"近 1.7 年有可交易的边际"，不能说"这是一个跨周期稳定的 alpha"。
3. **收益不来自 BTC 方向。** 净收益对 BTC 的回归 beta ≈ 0（−0.05 ~ −0.01），剥离 BTC 后 Sharpe 不降反升；跟全市场等权收益轻微
   负相关（−0.1 ~ −0.27），略偏"山寨币下跌时赚钱"。
4. **离验收红线还远。** 关卡3 红线是吃单下净 Sharpe ≥ 2.5，现在最好的一族中位数约 1.3，还没过 holdout。

---

## 2. 方法（怎么防止自欺）

- **口径核对**：`v2_official`（直接用正式模型打分）的验证段结果跟正式关卡3 的 `02_validation_base_cost.csv` 逐项相同；
  `v2_retrain`（本工具按同一配置重训）跟 `v2_official` 完全相同。评估和训练路径都跟正式流水线一致。
- **全程样本外**：每个模型都是滚动训练的，选择段和验证段的打分都是样本外。
- **挑配置只看选择段**：每个 case 的"最好组合"（映射 × 调仓频率 × 打分平滑）按**选择段**扣费净 Sharpe 挑，再看同一组合在验证段——
  验证段只用来确认。另外看**稳健性**：33 个组合的净 Sharpe 中位数、两段都为正的组合占比。
- **空仓过滤**：选择段空仓超过 20% 的组合不参与挑选（见 §4 第 2 条）。
- **holdout 没碰。**
- **仍然存在的偏差**：一共试了 48 个 case，每个 33 × 3 个组合——验证段上的"最好"数字天然偏乐观，应该看一片区域；B 组世坤因子名单
  本身是在选择段上选出来的。

## 3. 各因素的影响（同一配置下比较）

| 因素 | case | 结论 |
| --- | --- | --- |
| **标签形态** | `h6` vs `h6_raw` | **原始收益标签决定性地更好**：验证段净 Sharpe 中位数 −0.30 → +0.63。排名标签奖励"排名靠前"（中位数效应，第一版的问题），原始收益奖励"平均收益高"，后者才是 Top-K 等权赚的东西 |
| **标签持有期** | `h1_raw` / `h3_raw` / `h6_raw` / `h12_raw` | **1 天最好**。4 小时换手太高；12 小时、2 天都更差 |
| **训练窗口** | `h6_raw` / `_win180` / `_expanding` | 扩展窗口 ≥ 滑动 60 天 > 滑动 180 天。扩展窗口验证段最强，但训练慢 6 倍（约 11 分钟） |
| **随机种子** | `h6_raw` / `_seed345` / `_seed6789` / `_seed1013` | **单个模型极不稳定**：两组种子的打分逐期截面秩相关只有 0.43（扩展窗口 0.50），同一组合的净 Sharpe 能从 0.77 变成 0.08。集成必须做（`h6_raw_exp_ens9`、`h6_raw_ens14`） |
| **B 组（世坤因子）** | `h6_raw_noB` | **必须保留**：去掉后验证段中位数 0.63 → −0.77 |
| **C 组（市场状态）** | `h6_raw_noC` | 去掉后选择段明显变差（中位数 −0.71 → −1.36），验证段略降 |
| **流动性范围** | `h6_raw_p60` / `_p70` | 收窄到前 40% / 30% 没有稳定改善；而且早期币太少，top30 / top20 经常空仓 |
| **损失** | `h6_raw_l2`、`h6_raw_notail` | MSE 回归明显更差；去掉首尾加权在选择段更好、验证段更差，不稳定 |
| **标签中性化** | `h6_raw_neutral` | 更差 |
| **剥离打分的波动率暴露** | `v2_resid_vol(_beta)` | 更差：第二版模型的边际大部分就是低波动 |
| **单因子（不用 ML）** | `f_*` | 扣费后基本都亏。只有低波动（`f_vol_42`）两段都微弱为正（净 Sharpe 0.2–0.5）。收益类因子在 4h ~ 20 天各尺度都偏反转 |

## 4. 发现的方法问题（之后的研究都要注意）

1. **RankIC 高 ≠ 赚钱。** 第一版 RankIC 0.056 却不赚钱；Pearson IC 在所有 case 里都只有 0.005 ~ 0.013。评估至少要同时看
   首尾价差、打分对 vol_42 的暴露、扣费回测。
2. **早期币池小，宽 Top-K 会整段空仓。** 2022–2023 年掩码内每期只有 50–90 个币；top30 需要 60 个有效币才建仓，`h6_raw_p70` 的
   选择段几乎全程空仓，按选择段挑出来的"最好组合"其实只有 3 个月的数据。已经在评估里加了空仓比例并过滤（关卡3 本身有同名列）。
3. **迟滞宽度是绝对名次，币池变大后含义会变。** `top20_exit80` 在早期（每期 50–90 个币）几乎从不触发平仓，换手只有 0.015/根，
   等于静态组合；验证段（每期约 150 个币）换手 0.10–0.15。同一个参数在两段是两种策略，**建议改成相对分位的迟滞**（比如跌出前 40% 才平）。
4. **选择段和验证段的收益来源相反。** 选择段主要是多头腿赚、空头腿亏；验证段主要是空头腿赚。结合第 2、3 条，选择段的不成立可能
   有一部分是币池小造成的，不全是"信号失效"——还没拆清楚。
5. **单个模型的随机性很大**（见 §3），任何没做多种子集成的单次结果都不可信，包括第二版的正式结果。

## 6. 建议的下一步（需要你决定）

1. **把"持有 1 天 + 原始收益标签 + 多种子集成"做成正式配置。** 标签持有期可以只作为训练配置（`ml_training/config.py`），不用改全局
   `research_config.json`——关卡3 的回测本来就不依赖 IC 标签的持有期，阶段一的 IC 仍按全局口径做诊断。
2. **迟滞改成相对分位**，消除第 4 节第 3 条的口径漂移，然后重新比较两段。
3. **拆清楚选择段为什么不成立**：固定配置、按季度、按币池大小分组看；如果是币池太小，研究起点可以考虑后移，或者早期用更小的 k。
4. **执行成本**：盈亏平衡成本 10–80 bps 不等，挂单成交比例对结论影响很大；资金费率还没建模。
5. 以上定下来之后，**holdout 只跑一次**。

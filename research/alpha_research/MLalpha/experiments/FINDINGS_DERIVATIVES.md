# MLalpha 探索实验：OI / 多空比特征（2026-10-09）

> 研究起点 **2023-01-01**（`research_config.json`），选择段 2023-01-01 ~ 2024-06-30、验证段 2024-06-30 ~ 2026-03-15，
> holdout 没碰。结论已做成 `LgbmV3`（`sherpa/alpha/custom/ml/models.py`）；特征公式在 `sherpa/alpha/custom/ml/features.py`
> 的 `DERIVATIVE_FEATURES`。2026-10-10 正式流水线跑完 V3，结果见 §5：**验证段明显提升，选择段持平**——没有探索实验里那么干净。

---

## 1. 结论摘要

1. **多空比有用，进阶 OI 特征没用。** 在 LgbmV2 配置上只往 A 组加 4 个多空比特征（`DERIVATIVES_LS`），18 种子集成后：
   吃单净 Sharpe 中位数 选择段 −0.41 → **+0.12**、验证段 0.59 → **0.73**，两段都为正的组合 0.26 → **0.52**。
   只加 2 个 OI 特征（`DERIVATIVES_OI`）选择段明显变差（−0.18 → −0.78）。
2. **提升是选币能力，不是风格。** 剥离 6 个风格后的 `alpha_sharpe` 中位数 选择段 −0.27 → +0.25、验证段 0.60 → 0.84；
   `beta[low_vol]` 没有上升（0.27 / 0.42 → 0.21 / 0.40）。
3. **两组独立种子都成立。** `d_ls`（种子 0-8）和 `d_ls_s2`（9-17）选择段中位数 +0.26 / +0.17，是本批唯一两组种子选择段
   都为正的配置。OI + 多空比一起加（`d_core`）验证段更高（18 种子 0.94），但选择段换种子就翻负（+0.16 / −0.30）。
4. **9 种子集成仍然不够稳。** 同一个 `d_base` 换一组种子，选择段中位数 −0.18 → −0.60。比较新特征必须配对（同种子组）
   或用更多种子；V3 用 18 个种子。
5. 离关卡3 红线（吃单验证段净 Sharpe ≥ 2.5）仍然很远。

## 2. 数据

`market.fapi_ls_ratio_{5m,15m,1h,4h,1d}`，Binance vision 归档（`src_rank=3`）+ REST（`2`），跟 `fapi_oi_*` 同一套表结构和
时间语义（`start_time` = K 线开盘，值属于收盘 = `snap_time`）。接入 `BarPanel` 的字段：

| BarPanel 字段 | 库里列名 | 含义 |
| --- | --- | --- |
| `long_short_ratio` | `count_long_short_ratio` | 全体账户数多空比（偏散户情绪） |
| `top_account_long_short_ratio` | `count_toptrader_long_short_ratio` | 大户账户数多空比 |
| `top_position_long_short_ratio` | `sum_toptrader_long_short_ratio` | 大户持仓量多空比（按仓位加权） |

各带 `_high` / `_low`（rollup 桶内最高 / 最低）。读取：`CHReader.fetch_ls_ratio_history`（4h 按 `samples = 48` 过滤），
`ch_long_to_panel(..., ls_df=...)`；研究各子项目的 `load_universe_panel` 默认带上（`include_long_short_ratio=True`）。
2023 年起掩码内覆盖率约 99%（2022 年大户比大量缺失，研究段不受影响）。Binance 的 `sum_taker_long_short_vol_ratio`
没有入库：它 = 主动买量 / 主动卖量，K 线的 `taker_buy_volume` 已经有，A 组 `taker_buy_ratio_6` 是它的单调变换。

**实盘注意**：上游每小时 hh:05 开始补数、约 30 分钟补完，4h bar 收盘时最近一桶通常还不全（`samples < 48` 会被过滤成 NaN）。
上实盘前要决定推断等数据还是用上一桶。

## 3. 第一步：单变量扫描（筛候选）

口径：流动性前 50% 范围内截面排名；标签持有 6 根的原始收益（V2 口径）。看两段的 RankIC、**首尾 10% 价差**（bps / 6 根，
Top-K 等权赚的是这个）、**增量 IC**（特征对现有 A+B 组 25 个特征逐期截面回归后的残差的 RankIC，IR 按每 6 期取一点）、
跟 vol_42 的截面秩相关。

| 特征 | 公式 | RankIC 选 / 验 | 首尾价差 选 / 验 | 增量 IC_IR 选 / 验 | vol 相关 |
| --- | --- | --- | --- | --- | --- |
| `ls_global` | log(全体账户比) | +0.019 / +0.032 | **−40 / −17** | −0.10 / +0.02 | −0.25 |
| `ls_top_minus_global` | log(大户持仓比) − log(全体账户比) | −0.008 / −0.016 | **+35 / +18** | **+0.17 / +0.04** | +0.20 |
| `ls_global_z_42` | log(全体账户比) 的 42 根 z 分数 | +0.002 / +0.006 | −20 / −4 | **−0.13 / −0.09** | 0.00 |
| `ls_top_position_corr_42` | corr₄₂(Δlog 大户持仓比, 收益) | +0.031 / +0.025 | −1 / +4 | +0.03 / +0.07 | −0.32 |
| `oi_value` | log(OI × close) | +0.012 / +0.029 | +2 / +7 | **+0.10 / +0.11** | −0.19 |
| `oi_price_corr_42` | corr₄₂(Δlog OI, 收益) | −0.046 / −0.035 | −13 / −6 | **−0.12 / −0.13** | +0.28 |

注意 RankIC 和首尾价差的符号经常相反（`ls_global`：RankIC 为正、价差为负）——又是中位数效应，所以筛选看价差和增量，不看 RankIC。

淘汰的（扫描过的共 33 个）：

- 冗余：`tac_level`（大户账户比，跟全体账户比相关 0.96）、`tpo_vs_tac`（跟 `ls_top_minus_global` 0.97）、`tac_z_42`（跟 `ls_global_z_42` 0.90）、
  `oi_z_42`（跟已有 `oi_change_42` 0.71）；
- 波动率代理：`volume_to_oi_6`（vol 相关 0.60）、`oi_range_6`（0.52）、`gls_range_6`（0.39）——RankIC 很高（−0.06 ~ −0.08）但基本是低波动；
- 两段不一致或太弱：各种多空比 / OI 的 6、42 根变化、120 根 z 分数等。

## 4. 第二步：ML 消融（定特征）

`run_experiments.py` 第六批 case，全部是 LgbmV2 配置（持有 6 根、原始收益标签、扩展窗口），只改 A 组可选特征。
数字是全部组合的中位数（`summary.csv` / 关卡3 05·06 同口径的风格归因）。

| case | 特征 | 种子 | 吃单中位数 选 / 验 | 两段都正 | 毛 Sharpe 选 / 验 | alpha_sharpe 选 / 验 | 赚钱季度 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `d_base` | V2 原样 | 0-8 | −0.18 / 0.34 | 0.39 | 1.42 / 1.59 | 0.01 / 0.36 | 0.55 |
| `d_base_s2` | V2 原样 | 9-17 | −0.60 / 0.31 | 0.22 | 0.53 / 1.44 | −0.43 / 0.30 | 0.55 |
| `d_oi` | + OI 2 | 0-8 | −0.78 / 0.25 | 0.17 | 0.40 / 1.42 | −0.63 / 0.27 | 0.55 |
| `d_ls` | + 多空比 4 | 0-8 | **+0.26 / 0.67** | **0.57** | 1.22 / 1.84 | 0.28 / 0.70 | 0.64 |
| `d_ls_s2` | + 多空比 4 | 9-17 | **+0.17 / 0.68** | **0.50** | 1.41 / 2.02 | 0.19 / 0.75 | 0.64 |
| `d_core` | + OI 2 + 多空比 4 | 0-8 | +0.16 / 0.62 | 0.56 | 1.19 / 1.71 | 0.29 / 0.76 | 0.64 |
| `d_core_s2` | + OI 2 + 多空比 4 | 9-17 | −0.30 / 0.80 | 0.26 | 0.84 / 1.89 | −0.15 / 0.90 | 0.55 |
| `d_wide` | + 全部 10 个 | 0-8 | −0.20 / 1.15 | 0.37 | 1.16 / 2.44 | −0.10 / 1.29 | 0.73 |
| `d_base_ens18` | V2 原样 | 0-17 | −0.41 / 0.59 | 0.26 | 0.85 / 1.69 | −0.27 / 0.60 | 0.64 |
| `d_core_ens18` | + OI 2 + 多空比 4 | 0-17 | −0.19 / 0.94 | 0.41 | 0.97 / 1.96 | −0.11 / 1.10 | 0.64 |
| **`d_ls_ens18`** | + 多空比 4 | 0-17 | **+0.12 / 0.73** | **0.52** | 1.47 / 2.02 | **0.25 / 0.84** | 0.64 |

怎么读：

- 挑特征集只看选择段 + 稳健性：`d_ls` 两组种子选择段都为正、`both_pos` ≥ 0.5；`d_core` / `d_wide` 验证段更高，但选择段不成立，
  按规矩不能因为验证段好看就选它们（那是在验证段上挑）。
- OI 进阶特征单变量看起来不错（`oi_value` 增量 IC 两段都为正），进了模型却拖累选择段。可能原因：`oi_value` 跟 `quote_volume_42`
  相关 0.84，模型拿它做规模暴露，而规模在选择段（币池小）不赚钱。没有继续拆。
- 换手：`d_ls_ens18` 验证段 0.084 / 根，跟 base（0.086）相当，提升不是靠换手变化。

## 5. 正式流水线结果（2026-10-10，`run_track.sh`，只跑 V3）

研究线 `track.json` 加了 `alphas.include: ["custom.ml_lgbm_v3"]`、关卡2 透传只保留单因子（不做等权 / routed 混合）。V2 的对照数字
来自 2026-10-05 那次正式运行（本地备份在 `experiments/_cache/v2_baseline_20261005/`，不进 git），两次的数据、网格（39 个组合）、
成本口径完全相同。

**04 稳健性**（39 个组合的净 Sharpe 中位数，选择段 / 验证段，两段都为正的组合占比）：

| 成本 | V2 | V3 |
| --- | --- | --- |
| 零成本（毛） | 1.49 / 1.51，97% | 1.42 / **1.84**，92% |
| 全挂单 | 1.06 / 1.29，90% | 1.07 / **1.45**，87% |
| **全吃单（主口径）** | **0.03 / 0.21，49%** | **−0.11 / 0.56，44%** |
| 压力 | −1.15 / −0.70，8% | −0.92 / −0.28，18% |

**逐组合配对**（同一个映射 × 调仓频率，V3 − V2 的净 Sharpe）：验证段吃单 82% 的组合 V3 更好，中位差 +0.31；选择段吃单 56% 的组合
V3 更好，中位差 +0.05（毛收益中位差 −0.09）。即：**验证段普遍提升，选择段持平**，04 里选择段中位数从 +0.03 变成 −0.11 是分布的小幅移动。

**05 风格归因**（吃单，全部组合的中位数）：`alpha_sharpe` 选择段 0.22 → 0.09、验证段 0.13 → **0.62**（`alpha_t` 0.18 → 0.80）；
`beta[low_vol]` 0.23 / 0.42 → 0.19 / 0.41（没有更依赖低波动），`beta[reversal]` 验证段 0.16 → 0.23、`beta[momentum]` −0.04 → −0.14
（多了一点反转倾向）。

**06 分季度**：赚钱季度占比中位数两者都是 0.545（最高 0.727）；≥ 0.6 的组合占比 V2 41%、V3 23%。V3 的收益更集中：各季度吃单净收益中位数
2025Q1 +24%、2026Q1 +19%，2025Q3 −20%、2024Q1 −15%。

**02 具体组合**（验证段吃单）：V3 最好的一片是 top10 系、每 6 根调仓——`top10 | 每 6 根` 净 Sharpe 1.53（挂单 2.13）、年化 79%、最大回撤 −35%、
保本成本 23 bps；`top10_exit20 | 每 6 根` 1.47、保本 29 bps。V2 最好 0.92。全部组合中位数：保本成本 9.6 → 12.4 bps、年化 1.9% → 12.7%。
仍然没有组合过红线（≥ 2.5，且换手衰减 < 40%：最好几格衰减 0.47–0.57）。

**阶段一**（选择段 RankIC，按 regime 切片）：V3 跟 V2 几乎一样（全局 IC 0.029 → 0.030、IR 0.20 → 0.21），各 state 都显著（|t| ≥ 2.9）。

**跟探索实验的差别**：探索实验里 V3 配置选择段明显好于 base（18 种子 −0.41 → +0.12），正式运行里持平。原因主要在对照组：正式 V2 是种子 0-8
的一次抽样，选择段（+0.03）落在探索实验 base 的种子波动范围（−0.18 / −0.60）偏好的一端；探索网格（`evaluation.WEIGHTINGS`）跟关卡3 的
39 个组合也不同。结论：**多空比在验证段的提升是稳的（两套评估、多组种子都成立），选择段的提升没有在正式运行里复现。**

## 6. 建议的下一步

1. V3 要不要替代 V2 当基线由你决定：验证段吃单中位数 0.21 → 0.56、alpha_sharpe 0.13 → 0.62 是实质提升；但选择段没变好、收益更集中在少数季度。
2. 多空比在 C 组也可能有用（全市场散户情绪的聚合，比如掩码内 `ls_global` 中位数），这次没试。
3. 实盘接入前处理多空比的数据延迟（§2）。

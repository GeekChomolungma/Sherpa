# tradecraft 探索：放量蓄势（2026-10-28）

> 口径：跟正式研究线同一份数据（2023-01-01 ~ 2026-03-15，MLalpha 探索的面板缓存）、同一个流动性范围（成交额前一半）、同一套
> 关卡3 网格（39 个组合 × 4 种成本，`research/ml_training/evaluation.py`）。RankIC 标签 = `close[t+1] → close[t+1+h]`，h = 1 / 6。
> **挑选只看选择段**（2023-01 ~ 2024-06），验证段（~ 2026-03）只确认；holdout 没碰。脚本 `explore.py`、`diagnose_legs.py`，
> 规则代码 `sherpa/alpha/custom/tradecraft/liquidity_surge.py`（`LiquiditySurgeBase`）。

## 交易原则（用户）

1. 按截面的**短期流动性增量**排序，只在**流动性暴增**的币里交易（候选池）；
2. 池内打分：**放了量但涨幅变化率平缓、还没放量突破、没有长上影线**的分高；**已经放量突破、近期涨幅缩小（变化率为负、上涨衰竭）**的分低；
3. **横盘或频繁震荡**的行情不参与。

落地：候选池 = 最近 1 天平均成交额 / 最近 7 天平均成交额，在范围内排前 30%；池内三项各自做截面百分位排名再加权——涨幅变化率
（最近 a 根平均逐根收益 − 之前 a 根）、已经涨了多少（最近 b 根涨幅）、上影线（最近 s 根上影线占振幅的平均比例）；择时 = BTC
最近 7 天趋势效率（净位移 / 走过的路）低于过去 180 天的某个分位时整期 NaN。原话"全设成 0"改成 NaN：全 0 时所有币并列，
排序没有意义，Top-K 还会在并列里挑币开仓；NaN 才是不排名、不开仓。

## 结论

1. **候选池有用**：同样的打分，池内比全部币的 RankIC 高一倍（三项合成 0.030 vs 0.015，"涨得少"一项 0.033 vs 0.022）；
2. **三项里"还没涨出去"最强，"变化率平缓"其次，上影线最弱**；变化率按"越加速分越高"理解没有信号（选 / 验 +0.009 / −0.006），
   按原话"平缓的分高"（|变化率| 越小越好）就有（单独 0.022 / 0.032），三项合成后 6 根 RankIC 0.063 / 0.061；
3. **窗口拉长更好**：变化率、上影线看 1 天，涨幅看 2 天（`TcSurgeCalmV2`）——1 根 RankIC 0.042 / 0.042，6 根 0.077 / 0.061，选择段最好；
4. **跟 V4 打平**：6 根口径、同一段时间逐 fold 配对，V2 − V4 选择段 +0.011（t +1.0）、验证段 −0.009（t −1.4）、最近一年 ≈ 0，
   都不显著。三条规则的排序能力跟 30 个特征的模型一个量级；跟 V4 打分的截面秩相关只有 0.30 / 0.34（池内同一批币）；
5. **但 Top-K 等权多空扣费后不赚钱**：吃单中位数选 / 验 −1.8 / −2.1（V2），挂单也是负的，零成本毛 Sharpe 约 0。两个原因：
   - **空头腿被轧**：打最低分的是"已经冲高、涨幅在缩小"的币。它们的中位收益确实更低（所以 RankIC 是正的），但右尾极肥——
     最低分组 6 根收益的 99% 分位 +29% ～ +36%，最高分组 +17% ～ +19%。等权做空这一组，少数继续暴涨的币把多数回落赚的钱全吃掉
     （选择段空头腿年化 −15% ～ −19%）。这跟 ML 第一版的"中位数效应"是同一类问题：排序对、平均收益不对；
   - **换手高**：池子成员每根都在变，换手 0.27 ～ 0.31 / 根（V4 0.15），保本成本 2 ～ 4 bps，低于吃单 8 bps；
6. **原则 3（横盘不参与）数据不支持**：关掉 BTC 趋势效率最低的 20% / 33% / 50% 时段后，剩下时段的 RankIC 基本不变
   （33%：选 / 验 0.034 / 0.041 vs 不择时 0.036 / 0.041），这套排序在震荡期并不比趋势期差；收益、回撤只有小幅变化；
7. **"已经暴涨的不碰"也不行**：池内涨幅前 10% / 20% / 30% 直接不参与，RankIC 一路掉（6 根 0.063 → 0.046 / 0.040 / 0.032），收益没改善。

试了四批共 35 个参数组合，挑选只看选择段；数字已经在验证段上看过，后面不要再按验证段调参。

## 往下可以做的

- **跟 V4 合成**：排序能力跟 V4 一个量级、打分相关只有 0.3，是跨模型合成有用的前提（之前 LSTM + 树模型合成验证段 Sharpe 翻倍）。
  需要关卡2 真跑，或者在叠加层里做；
- **空头腿不做"冲高的币"**：问题在空头那一头的肥尾，多空对称的 Top-K 改不了。要么只拿池内高分做多、用别的东西对冲，要么空头腿换来源——
  都超出了"截面 Top-K 多空"这个框架，要先定组合构建方式；
- **原则 3 换个定义再试**：这里只试了 BTC 趋势效率。"横盘"也可以是截面层面的（全市场离散度低、普涨普跌少），但要先确认排序在那种
  时段真的变差，不然择时只是少赚。

## 第五批：只做多 + 持有 2～3 根（用户的改进，2026-10-28）

改动：① 只买 Top-K、不做空（亏钱的是空头腿）；② 持有时间压到 2～3 根 bar（8～12 小时）。

- 实例 `TcSurgeCalmV2H2` / `V2H3`：打分跟 V2 完全相同，只是 `horizon_bars` = 2 / 3（步骤 0 的 RankIC 按 2 / 3 根算）；
- 回测：关卡3 的组合都是多空对称的（不改），只做多在 tradecraft 研究线的**步骤 6**（`run_long_only.py`）单独算——同一套 Top-K / 迟滞 /
  调仓零件，只留多头一侧放大到满仓，调仓每 2 / 3 根，7 种映射 × 2 = 14 个组合；同时算两个等权基准（同样调仓、同样扣费）：
  `ew_scope` 等权买范围内全部币、`ew_pool` 等权买整个候选池。产出 `runs/<id>/results*/long_only/`。

结论：

1. **池内选币在多头一侧是有效的（零成本）**：大部分 Top-K 组合两段都跑赢"等权买整个候选池"（零成本超额 Sharpe 每 3 根时 0.3～1.0），
   top5 / q10 最明显；
2. **但只做多吃满了大盘**：Beta ≈ 0.94，验证段（2024-07 ～ 2026-03）山寨币整体大跌，等权买全范围吃单年化 −55%、最大回撤 −87%，
   Top-K 只做多也一样跌 −86% ～ −98%。不做空 = 失去了对冲，收益基本由大盘决定；
3. **换手更高**：满仓只做多、池子成员每几根就换，换手 0.48（每 3 根）～ 0.62（每 2 根）/ 根，吃单把零成本的超额全部吃掉；
4. **持有 3 根好于 2 根**（换手低一截，RankIC 也更高）。

只做多没有解决问题，反而把大盘风险引进来了：选币超额真实存在，但量级（零成本超额 Sharpe 0.3～1.0）扛不住 0.5 / 根的换手成本。

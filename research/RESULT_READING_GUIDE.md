# research 结果解读指南

> 每次跑完 `run_research.sh`，按本文的顺序读结果、下结论。
> 目标是让每一次的判断都有同一把尺子，而不是看哪个数字大就选哪个。

---

## 0. 先确认这次跑的是什么

打开结果之前，先核对 `run_research.sh` 启动时打印的三行，写进自己的笔记里：

| 打印项 | 看什么 |
|---|---|
| `[研究配置]` | 研究段起点、`validation_start`（选择段 / 验证段的分界）、`research_end`；`label` 里的执行延迟和持有期 |
| `[显著性门槛]` | 04 / 05 矩阵的 \|t\| 门槛（默认 3） |
| `[模式]` | 是否中性化（正式结论只看中性化版本） |

**配置变了，结论就不能跟上一次直接比**，尤其是时间切分和执行延迟。

三段切分的含义（详见 [`README.md`](README.md)「统一研究配置」）：

```text
research_start ── 选择段 ── validation_start ── 验证段 ── research_end ── holdout ── holdout_end
                 选因子、估方向/权重              比较方案                  最终方案只跑一次
```

---

## 1. 各阶段产物：按漏斗顺序快速过一遍

| 阶段 | 文件 | 重点看 |
|---|---|---|
| 阶段一 | `regime_factor_report/results/04_regime_matrix.csv` | 每个 regime state 的 Top K；`significant_count / candidate_count`（多少因子过了 \|t\| 门槛）；`low_sample` |
| 阶段一 | `regime_factor_report/results/05_global_matrix.csv` | 不看 regime 的全局 Top K（G0 的来源） |
| 关卡1 | `factor_orthogonalization/results/02_regime_cluster_assignments.csv` | 每个 state 的 `keep` 名单；被 `drop` 的因子和它的 `redundant_with`；相关系数接近阈值 0.7 的因子对 |
| 关卡2 | `factor_synthesis/config.py` | 刷新后的两份候选池（`REGIME_FACTOR_SETS`、`GLOBAL_FACTORS`），行尾注释有 IC_IR 和冗余簇 |
| 关卡2 | `factor_synthesis/results/01_scheme_comparison.csv` | **方案比较的主表**，按下面第 2 节的步骤读 |
| 关卡2 | `factor_synthesis/results/03_factor_weights.csv` | 各方案实际使用的方向和权重 |
| 关卡2 | `factor_synthesis/results/04_yearly_ic.csv` | 分年 IC，判断预测力是否衰减 |

前面几个阶段的产物主要用来**确认上游没有异常**（比如某个 state 显著因子突然变成 0 个、keep 名单大换血）。
真正做决策的是关卡2 的对比表。

---

## 2. 读关卡2 方案对比的七个步骤

`01_scheme_comparison.csv` 已经排好序：验证段在前、合成方案在前，同组内按 IC_IR 从高到低。
**方案比较只看 `segment` 以 `validation` 开头的行**，选择段的行是样本内，只作参考。

### 第 1 步：看验证段样本量，判断差距是不是噪声

经验公式：**IC_IR 的标准误 ≈ 1 / √样本数**。两个方案的 IC_IR 差距要超过约 **3 / √样本数**，才算真有差别。

| 验证段样本数（4h bar） | 大约对应 | 能分辨的最小 IC_IR 差距 |
|---|---|---|
| 450 | 2.5 个月 | 约 0.14 |
| 1500 | 8.5 个月 | 约 0.08 |
| 3300 | 18 个月 | 约 0.05 |

这个公式没考虑 IC 的自相关，实际门槛还要更大一些。

**差距没超过门槛就当作打平，选更简单的方案**（因子更少、没有路由、没有加权）。

### 第 2 步：合成方案有没有打赢最强的单因子

对比表里 `kind=single` 的行是每个候选因子单独使用的表现。
合成方案的 IC_IR 至少要明显高于其中最强的那个，否则合成没有意义，直接用单因子更简单。

### 第 3 步：L1 对比 G0 —— 加权有没有增量

L1 按选择段的 IC_IR 加权，G0 等权，两者用的是同一批因子。
先看 `03_factor_weights.csv` 里 L1 的权重：如果各因子的权重都接近等权，两者结果必然接近，
这时"加权没有增量"就是预期之内的结论。

### 第 4 步：G0 / L1 对比 L0 / L2 —— 按 regime 选因子有没有增量

- **G0 / L1**：选因子和合成都不看 regime；
- **L0**：各 state 名单的并集等权（选因子看了 regime，合成不看）；
- **L2-某维度**：每根 bar 用当前 state 的名单（选因子、合成都看 regime）。

L0 / L2 要明显好于 G0，才说明 regime 框架值得它带来的复杂度（更多因子、路由逻辑、更高换手）。
只有一次验证段里某个 L2 名义上领先，而且差距在噪声以内，不算证据。

### 第 5 步：同一方案，选择段对比验证段 —— 查过拟合

| 现象 | 含义 |
|---|---|
| 验证段略低于选择段 | 正常，样本外总会打点折扣 |
| 验证段远低于选择段 | 过拟合：方案在选因子的那段数据上占了便宜 |
| 验证段反而远高于选择段 | 不正常，要找原因。常见的是两段数据质量不同，比如早年可交易币太少、IC 噪声大 |
| 自由度大的方案（L2）在选择段领先、验证段落后 | 典型的样本内偏差，恰恰说明三段切分有必要 |

注意：**IC 水平只在同一段内部比较才有意义**，两段之间的差异可能来自市场本身，不一定来自方案。

### 第 6 步：看 `score_autocorr` —— 换手预警

它是相邻两期分数的截面相关：越接近 1，排序越稳定、换手越低。
IC 差不多时，选更稳定的方案；接近 0 的因子几乎每根 bar 都在重排，到关卡3 扣成本时会很吃亏。

### 第 7 步：看分年表 —— 预测力是否衰减

读 `04_yearly_ic.csv`（运行时终端也会打印一张"方案 / 因子 × 年份"的 IC_IR 表）：

- **逐年大致稳定**：老数据仍然有价值，固定窗口 + 定期重跑就够了；
- **逐年明显下降**：预测力在衰减，考虑缩短训练窗口或做滚动重训；
- **单个因子最近一年突然变弱**：记进观察名单。样本很少的年份（比如当年只过了几个月）先别急着下结论。

---

## 3. 下结论的原则

1. **复杂度必须换来明显的提升**。打平时选更简单的方案。
2. **只凭验证段下结论**，选择段的数字不能作为证据。
3. **不要在验证段上反复试变体**。比较的方案越多，验证段就越接近样本内，挑出来的赢家越可能是运气。
4. **holdout 只在方案定稿后用一次**，结果如实记录，不回头调参。
5. **每次的结论和当时的配置一起记下来**，方便以后对照（配置一变，结论可能也跟着变）。
